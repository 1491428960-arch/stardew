# 「找话题」话题塌缩的第二层根因：素材不轮换（2026-09-23）

> 分支：`codex/story-memory`　｜　范围：`bridge/`（**未改动任何源码，本轮全部实验已回退**）
> 触发：用户实测 14 心、**连点四次「找话题」，四次说的是同一个东西**
> 上一轮：`docs/report-topic-intent-2026-09-22.md`（那份报告修了指令矛盾 + 话题池 + 锚点借用）

---

## 0. 一句话结论

**每一轮「找话题」递进 prompt 的素材卡，逐字完全相同。**

`prompts.py:5616` 把样本卡切成 `[:1]`（取排序第一条），而样本选择
**完全不感知对话历史**（访问器没有 `history` 参数），topic 路径下 `player_input`
又恒为空串 ⇒ **排序是确定性的** ⇒ 每轮取到的是同一条。

模型不是"不听话"，是**输入从头到尾没变**。上轮修好的指令矛盾、话题池、锚点借用
都作用在「怎么说」上，而这一层坏在「说什么的素材从哪来」。

## 1. 决定性证据：连续四轮素材卡逐字比对

工具：`.tmp/topic-probe/turn-probe.py --dry-run`（走真实入口
`app._build_context(compact_prompt=True)`，用既有探针里的**真实回复**构造递进 history）。

```
──── 第 1 轮（history 0 条，共 21 张卡）────
  voice_card        6 条  嘿，你好。很高兴见到你！｜我想找个时间去爬山！…
  speech_evidence   1 条  嘿，你好。很高兴见到你！
  style_evidence    1 条  嗨，伙计们！
  knowledge_facts   1 条  生活与葡萄园、酿造和角色扮演（缝纫、手工）有关。
──── 第 2 轮（history 1 条，共 21 张卡）────   ← 四张卡与第 1 轮逐字相同
──── 第 3 轮（history 2 条，共 22 张卡）────   ← 逐字相同
──── 第 4 轮（history 3 条，共 23 张卡）────   ← 逐字相同

素材卡是否逐轮变化（逐字比对）
  voice_card        ❌ 全部相同 ⇒ 素材不轮换
  speech_evidence   ❌ 全部相同 ⇒ 素材不轮换
  style_evidence    ❌ 全部相同 ⇒ 素材不轮换
  knowledge_facts   ❌ 全部相同 ⇒ 素材不轮换
```

**卡片总数在变（21→22→23），history 在增长，四张素材卡一字未变。**

### 1.1 为什么这是结构性的，而不是偶然

`profile_index.py` 的访问器签名（L2224）：

```python
def speech_evidence(npc_id, source_mods, *, relationship_stage="",
                    player_input="", limit=6, completed_event_ids=()):
```

**没有 `history`。** 选择只由「角色 + 阶段 + 本轮玩家输入 + 已完成事件」决定。
topic 路径下 `prompts.py:5590-5593` 显式把 `player_input` 清空：

```python
if topic_request:
    # topic 是 NPC 主动开口的系统意图，不存在本轮玩家输入。
    player_input = ""
```

⇒ 每轮调用参数完全相同 ⇒ 返回结果完全相同 ⇒ `[:1]` 取到同一条。

## 2. 四组对照实验（单轮采样，各 30 次独立请求）

单轮采样只测**首轮话题分布**（无 history ⇒ 槽位机制不参与），
所以它衡量的是「素材基线」，不是「轮换效果」。

| 实验 | 变量 | 主域个数 | 葡萄园/酿酒 | 作画/手工 | 家务/居家 | 提到「葡萄」 | 玩家/关系提及 |
|---|---|---|---|---|---|---|---|
| **基线** | — | **6** | 33.3% | 10.0% | 33.3% | 40.0% | 96.7% |
| **A** | 知识卡 1→2 条 | 6 | 26.7% | 16.7% | 40.0% | 30.0% | 86.7% |
| **B** | 样本卡 `[:1]`→`[:4]` | **4** | **46.7%** | 10.0% | 40.0% | **53.3%** | **100.0%** |
| **C2** | 解锁事件 + `[:4]` | 4 | 40.0% | **23.3%** | **23.3%** | 36.7% | 93.3% |

**读法（诚实标注）**：n=30，各格差值都在噪声范围内（例如 10/30 vs 8/30，
Fisher 精确检验 p≈0.78）。**per-cell 都不显著**，但三条结构性事实成立：

1. **A（放宽知识卡）无效**：33.3%→26.7% 的方向对，但两项合计 66.6%→66.7%，
   总量只是从「葡萄园」挪到「家务」。知识卡 1→2 条不是瓶颈。
2. **B（单独放宽样本卡）有害**：主域 6→4，葡萄 40%→53.3%，玩家/关系 96.7%→100%。
   **因为多取的 3 条与 `voice_card` 那 6 条锚点是同一类句子**（打招呼/邀约/问玩家），
   同一套模板被强化了两遍。**数量放大只是放大模板。**
3. **C2（解锁事件 + 放宽）方向最好**：作画/手工提及率 20%→40%（翻倍，新高），
   家务/居家 63.3%→40%（大降）。但**主因是解锁了事件语料**，不是放宽切片。

## 3. 根因链（四层，逐层都有实测）

### 3.1 排序层 —— 本次新发现（最根本）

`profile_index._select_evidence_candidates` 的候选排序元组，**七个键在 topic 路径下全部并列**，
唯一区分度是最后一位 `original_index`（索引里的物理位置）。实测打点
（`.tmp/topic-probe/order-probe.py`）：

```
   topic  stage  evPri  magic  keyPri  pathPri  srcPri     idx   text
       0      0      1      0      -1        4     -20    4799   嗨，伙计们！
       0      0      1      0      -1        4     -20    4801   是的。皮埃尔总有我需要的东西！
       0      0      1      0      -1        4     -20    4803   嘿！
       0      0      1      0      -1        4     -20    4806   好耶！
       0      0      1      0      -1        4     -20    7130   加油，斯嘉丽！让那些葡萄看看谁才是老大！
       0      0      1      0      -1        4     -20    7133   ！！！
```

**没有任何一个维度衡量「这句话有没有内容」。** 于是永远取索引里物理位置最靠前的那几条，
而它们正好是 eventId `5000009` 里的应答语（「嗨，伙计们！」「嘿！」「好耶！」「！！！」）。

**同一缺陷的第二处实现**：`speech.py:_voice_anchor_candidates`（L437-540）的排序键
最后一位同样是 `original_index` —— 这解释了为什么 `voice_card` 那 6 条锚点
永远是问候/邀约句。

### 3.2 切片层 —— 本次新发现

`prompts.py:5615-5617`：

```python
        if compact:
            speech_evidence = speech_evidence[:1]
            style_samples = style_samples[:1]
```

- 这是**全文件唯一没有注释的切片**，而同一文件其他每一处切片都带长篇理由
  （L5889-5895 有 7 行说明「常驻事实不参与这一刀 `[:1]`」）。
- 它与两个常量**直接矛盾**：`_MAX_SPEECH_EVIDENCE = 4`、`_MAX_STYLE_SAMPLES = 3`
  在它**之后**执行，**永远不可能生效**。
- 实测损失：`speech_evidence` 6 条 → **1 条**（−83%），`style_evidence` 8 条 → **1 条**（−88%）。

（`knowledge_facts` 另有一处独立切片：`prompts.py:6536-6542` 的
`rolling[:(1 if _is_plain_dialogue_input(player_input) else _MAX_KNOWLEDGE_FACTS)]`，
`_MAX_KNOWLEDGE_FACTS = 2`。）

### 3.3 准入层 —— 上轮已部分触及

索菲亚 310 条语料的 `evidenceKind` 构成：

| kind | 条数 | 占比 | 能否进 prompt |
|---|---|---|---|
| `event_dialogue` | 205 | 66% | 受 `completedEventIds` 门控 |
| `marriage_dialogue` | 78 | 25% | `is_stable_voice_evidence_record` 直接 `return False` |
| `dialogue` | 26 | **8%** | ✅ 唯一畅通的来源 |
| `extra_dialogue` | 1 | — | ✅ |

**⚠ 这条路不要走**：§5 记录，上轮已经试过把事件对白补进锚点，**结果是变差**。

### 3.4 轮换层 —— 缺位（与 3.1–3.3 叠加成完整因果）

素材卡不轮换（§1），而上轮 `report-topic-intent-2026-09-22.md` §7.2 已查明：
唯一能换话题的部件 `stage_execution_card.topicSlot` 依赖 history 的 facet 历史，
但阈值 `_FACET_LOOKBACK = 3` / `_FACET_REPEAT_THRESHOLD = 2` 经常够不到
（acquaintance / friend 都没触发）。

**两层叠加** ⇒ 槽位几乎不触发，素材又完全不变 ⇒ **话题必然塌缩**。
即使槽位触发、给出「换个面」的指令，她手里也只有同一条素材可用。

## 5. 上一轮已排除的路（**不要重复走**）

`report-topic-intent-2026-09-22.md` §4.5 与 §11 已经验证过：

> 第一版没加闸时补进来的是**事件对白**（sourceKey 形如 `3691380/f Scarlett 125/t 600 1800/…`），
> 即她**在事件里对别人**说的话（「加油，斯嘉丽！」），把 stranger 的 4 条锚点挤掉了 3 条
> —— **比修之前更差**。

**本轮 C2 独立复现了同一现象**：解锁事件后 `speech_evidence` 变成
「嗨，伙计们！」「是的。皮埃尔总有我需要的东西！」（群聊/商店应答语）。
上轮最终采用的方案是「只借**有阶段标注的更早阶段**原文，且排除事件对白键」。

⇒ **结论：单纯"解锁事件语料"是错误方向。**

## 6. 修法方案（待拍板，三者可组合）

### 方案 A：素材按轮次轮转（**推荐，直击 §1 的机制**）

在 `prompts.py:5615-5617` 那处，把「永远取第 1 条」改成「按对话轮次从候选池里取第 k 条」，
k 由 history 长度决定（并对候选池取模）。

- **优点**：不改排序、不改准入、不动数据；一处改动；
  长期对话会**遍历整个候选池** ⇒ 直接命中用户要的「长久的聊」。
- **风险**：需要 history 长度可用（`context` 里有）；需决定池子大小（建议与
  `_MAX_SPEECH_EVIDENCE = 4` 一致）。
- **验证**：`turn-probe.py --dry-run` 应显示四轮素材卡**不再相同**；再跑多轮实机对照。

### 方案 B：修排序，注入内容质量维度（治本，但影响面大）

在 `_select_evidence_candidates` 的排序键里，用「内容优先级」替代/补充 `original_index`
（例如按文本长度分档、或过滤 <8 字应答语）。`speech.py:_voice_anchor_candidates` 同改。

- **优点**：`voice_card`、`speech_evidence`、`style_evidence` 三处一起受益。
- **风险**：影响**所有角色所有阶段**的锚点与样本 ⇒ 必须出全量漂移表（做法见上轮 §11 的覆盖统计）。
- **注意**：单独做这个而不做 A，仍解决不了「四轮同一张卡」。

### 方案 C：把 `preferredTopics` / `topicPool` 接进选择逻辑（面向「话题丰富」）

这两份数据现在完全没参与选择。可让 topic 路径按轮次从中轮转取一个话题方向，
再据此检索候选（用 `player_input` 或新增参数把方向传进访问器）。

- **优点**：话题多样性有明确的、可枚举的来源；`_topic_hints` 那套词汇
  （魔法/边界/不确定/干燥幽默）对索菲亚**完全打不着**，而 `preferredTopics` 是她自己的。
- **风险**：改动跨 `personas/sve.json` + `profile_index` + `prompts` 三层。

### 方案 D（上轮遗留，需一并拍板）

`stage_policy.py` 的 `_FACET_LOOKBACK = 3` / `_FACET_REPEAT_THRESHOLD = 2`：上轮判定
「槽位触发时有效，但阈值够不到」，**未改**，属全局行为参数。

**建议组合：A + D 先行**（各自独立、可归因、影响面可控），B/C 作为第二轮。

## 7. 方法论教训（新增）

1. **单轮独立采样测不出轮换问题**。我最初 120 次采样全是「每次新进程 + 单轮」，
   于是槽位机制根本没参与，却差点把结论下成「话题池无效」。
   **要测「聊天的变化」，探针必须带 history 连续跑。**
2. **「素材卡逐轮是否变化」应该成为一个常驻检查**：`turn-probe.py --dry-run` 零额度、
   几秒出结果，能在改动前后立刻看出轮换是否生效。
3. **`[:1]` 这类无注释切片是高风险信号**：同文件其他切片都有长篇理由，
   唯独它在与两个常量矛盾的情况下裸切。**"唯一没有注释的那一处"值得优先怀疑。**
4. **排序键的最后一维如果是 `original_index`，等于没有排序** ——
   它只是把「索引构建顺序」当成了语义。两处独立实现（`profile_index` 与 `speech`）同病。

## 9. 方案 A 已落地：素材按对话轮次轮转（2026-09-23）

用户拍板方案 A。改动 `bridge/src/stardew_ai_bridge/prompts.py`（**+39 −3 行**）：

1. 新增模块级 `_rotate_evidence_by_turn(candidates, turn_index, pool_size)`：
   在**排序后的前 `pool_size` 条**里按 `turn_index % len(pool)` 取 1 条。
   候选为空返回 `[]`；池子只剩 1 条时恒返回该条；拿不到轮次时退回第一条（= 原行为）。
2. `PromptBuilder.build` 的 `if compact:` 块：`speech_evidence[:1]` / `style_samples[:1]`
   换成轮转调用，轮次取 `turn_index = len(context.get("history") or ())`。

### 9.2 诚实标注的局限

轮转池 = 排序前 4 条，而它们仍然是「嘿，你好。很高兴见到你！／我想找个时间去爬山…／
哦，你今天过得怎么样…／我在想也许我们可以找个时间去旅行…」——**问候 / 邀约 / 问玩家 / 邀约，
四条都不含实质话题**。

⇒ **方案 A 消除了「四次说同一个东西」，但没有拓宽话题。** 这是预期内的：
它只改「取第几条」，不改「池子里有什么」。**要拓宽话题仍需方案 B（排序注入内容质量维度）。**

### 9.4 一处认知修正（值得记）

`prompts.py` 的换行符本轮实测为**纯 LF**（`CRLF: 0　裸LF: 7607`），
此前「它是 CRLF」的判断**有误**。误判使第一版补丁的替换串（用 `\r\n` 拼接）全部匹配不到 ——
好在补丁写成「匹配不到即报错退出」，**没有写坏文件**（`git diff` 为空）。

git 侧有 `LF will be replaced by CRLF` 警告，说明仓库存储与工作区换行符不同，由 git 自行处理。

**教训：文件换行符必须实测，不能沿用记忆。**
