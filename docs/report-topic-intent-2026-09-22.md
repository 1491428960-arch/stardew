# 「找话题」路径排查与修正（2026-09-22）

> 分支：`codex/story-memory`　｜　范围：`bridge/` + `data/personas/`（**未动 `smapi/`**）
> 触发：用户实测「**索菲亚六句话里面四句关于画**，并且**说话文艺腔太重，不贴角色**」
> 上一轮（`7b9aa33`）已把人设、`stage_policy`、评测案例里的"绘画"清干净，**但玩家实测仍在聊同一类话题**。

---

## 0. 一句话结论

上一轮的修改方向对，但**漏了这条意图路径自己的卡片**：

- **`intent="topic"`（游戏端「找话题」）没有本轮玩家输入**（`app._build_context` 与
  `smapi/BridgeClient` 都会把 `message` 清空），可这条路径上**四张卡全都在要求她"回答/接住玩家"**；
  同时 `topic_response_contract` 又写着「可以主动开启新话题」——模型收到互相排斥的目标。
- **`stageProfiles.<stage>.topicPool` 是一份"新生效的旧数据"**：它过去因为一个缩进缺陷
  **从来没进过 prompt**（2026-09-21 才修），而前几轮把 `preferredTopics` 换成具体物时，
  这份抽象元类目刚好开始生效，净效果互相抵消。
- 云端复跑 12 轮后，**"画"没复现，但复现了同一个病的另一种形态**：话题塌缩到「酿酒 + 颜色」这一面。

## 1. 「找话题」路径的完整链路

### 1.1 两条路径的卡片清单（实测）

`intent="topic"`、`compactPrompt=true`。**游戏端与评测端不是同一条路径**——
游戏端请求体（`BridgeDialogueRequest`）**不带 `qualityContext`**，因此 `naturalMode` 不是 True。

| 组合 | 卡片数 | 卡片清单 |
|---|---|---|
| **游戏端 · 找话题（真实）** | 15–17 | `safety_rules` `persona_core` `story_state` `mod_overlay` `scene` `daily_routine` `conversation_history` `post_history_voice_guard` **`stage_execution_card`** `voice_execution_card` **`topic_response_contract`** `final_role_voice_contract` `player_echo_guard` **`turn_plan`** `topic_trigger`（dating 及以上另加 `affection_initiative` `affection_priority_final`） |
| 评测端 · 找话题（runner） | 19–21 | 同上，但**换成** `quality_context` `natural_dialogue_contract` `natural_role_texture` `voice_card` `knowledge_facts` `behavior_examples` `natural_topic_role_override` **`sophia_liveliness_final`** |

> ⚠ **探针口径提醒**：用 `scripts/run_character_quality_eval.py` 的 `_build_context` 做探针会注入
> `naturalMode=True`，看到的是**评测路径**（多出 `sophia_liveliness_final` 等 4 张评测专属卡）。
> 要复现线上，必须走 `stardew_ai_bridge.app._build_context`（= `/api/context/preview` 的入口）。

### 1.2 为什么没有 `conversation_lead` 卡

`prompts.py` 的 `conversation_lead` 卡有两个硬条件：

```python
if interaction_intent == "chat" and not runtime_compact:
    conversation_lead_card = _build_conversation_lead_card(...)
```

- `intent == "topic"` → 第一条不满足；
- 游戏端 `compactPrompt=true` → `runtime_compact=True` → 第二条不满足。

**但 `{topicPool}` 并没有缺席**：`build_stage_policy` 产出的 `conversationLead.roleGuidance`
照旧进了 `stage_execution_card` 的 JSON 字段，里面渲染的正是 `preferredTopics`：

> 「落点在**酒窖里这一批新酿、给下一个角色扮演挑的布料、镇上今天谁在广场上吵、记得刚搬来那阵子住的那间旧房子、加了桦树糖浆的爆米花食谱、窝在毯子里看电视**之间轮换；…」

所以线上同时有**两份话题数据**：`roleGuidance` 的具体物（`preferredTopics`）
与 `persona_core.stageProfile.topicPool` 的抽象元类目。

### 1.3 为什么没有 `topicSlot`（不是 bug）

`topicSlot` 由 `rotation_topic_slot()` 产出，三个触发理由都是**基于历史**的：

- `facetRepeat`：最近 `_FACET_LOOKBACK=3` 轮里同一生活面出现 `≥ _FACET_REPEAT_THRESHOLD=2` 次；
- `playerShortReply`：玩家的回话净字 ≤6 且整句由空转词拼成；
- `playerAsksNewTopic`：玩家说「换个话题」。

**首轮"找话题"三者都不成立**（没有历史、没有玩家输入），所以槽位为空是正确行为。
另外 `_natural_stage_execution_payload` 会 pop 掉 `initiative` 等字段，**但不 pop `topicSlot`**。

### 1.4 `topic_response_contract` 全文（游戏端实测原样）

```json
{
  "continuationMode": "anchored",
  "instruction": "自然找话题时，可以从当前情境里说一件眼前小事，也可以从角色自己的近况、记忆或兴趣里主动带出新话题；只输出 NPC 会发出的中文消息，不等待或回应不存在的玩家句子。继续入口可以省略，不要为了把话题交出去硬加问题、二选一或安排；不要把普通分享扩写成完整的情绪—话题—邀约结构。玩家没有先提比喻、海风或光线时，默认不用比喻；能用事实、动作或短感受说清就不要改写得更漂亮。不要把样例中的事实当作当前剧情，也不要凭空完成未确认的邀约或事件。允许从角色自己的近况、记忆、兴趣或眼前观察主动开启新话题，不要求玩家先铺垫；但第一次提到一个新对象、事件、人物或记忆时，必须在同一条消息给出最小背景：它是什么、刚发生了什么，或为什么此刻想到它；无论话题从哪来，都必须有一句来源句，说清它是从哪来的（比如刚做了什么、最近在弄什么、刚才看到了什么），不能把它当成双方已经知道的东西；说清来源的起手式每轮自然变化，不要反复用同一个开头。顺序可以换，来源不能省：开场那一拍按角色自己的说话习惯来（角色卡里 signatureMoves、sentencePattern 怎么写就怎么开口），但这一拍只算一声反应或短招呼（十个字以内，如‘哇’‘等等’‘你来啦’），不含新对象、不含指代——‘它／这个／那个’这类还没交代过的指代，以及‘还没干透’这种省掉主语的描述，都不能拿来起句；同一条消息里必须有来源句，位置在开场那一拍之后。不要为了先交代来源而省掉这一拍，也不要用‘X 不会…’‘X 还是…’这类预设对方已知的句式开头。玩家不需要知道此前未说过的前提；不要只说‘那件事、那首歌、最近那个、后来怎么样了’，也不要用‘你还记得吧’把缺失背景推给玩家。说完后给玩家留一个能接的口子，三选一：一个真问题、一件把玩家拉进来的具体事、或一个玩家已知的共同对象；口子不一定是问句。只留一个口子就够，不要堆问题，也不要用命令或提醒代替口子。✗ 不能这样：‘记录簿不会长腿跑掉。倒是你，今天看起来没怎么好好休息，得先坐下，别站在塔里晃。’✓ 应该这样：‘我刚把今天的记录簿合上——上面半页星图怎么算都不对。你今天在农场忙完了吗？’✓ 招牌动作是‘先脱口说第一反应’的角色，反应拍和来源句要在同一条消息里一起出现：‘哇——我刚把晒好的床单收进来，还热乎着。你要不要帮我叠一半？’三条示例只示范反应拍、来源句和口子这三个步骤，句式和对象随角色与场景变化，里面的事实不要当作当前剧情。示例只示范步骤，不要模仿其中的比喻、温度、光线、气味或‘好看’‘顺眼’这类审美评价；把一件小事用日常说法讲清楚就够，不要为了好听换一个更漂亮的说法。这个角色的招牌动作就是在句首选脱口而出的第一反应：……answer_only 仍然不追问、邀约或安排，但允许同一条消息用2到4个独立短句完成这组连续节拍。",
  "topicKeywords": [],
  "topicSeed": ""
}
```

（上面是**已修正后**的版本；修正前的差异见 §3.3。`topicSeed` / `topicKeywords` 为空——
它们是评测套件专用注入，**游戏端不带**。）

### 1.5 矛盾点（**5 处**，不是 1 处）

`topic` 路径**没有当前输入**，但这四张卡/字段都在要求"回答"：

| 位置 | 字段 | 修正前原文（stranger） |
|---|---|---|
| `stage_execution_card` | `initiative` | **不主动开启新话题，不为延长对话而反问** |
| `stage_execution_card` | `responseShape` | 轻柔地用 1 句**回答**；… |
| `stage_execution_card` | `instruction` | 直接**接住玩家的意思**…表达预算：直接**回答后**最多追加一个动作 |
| `turn_plan` | `instruction` | 先**回答**，再给一个具体、轻量的继续入口 |

> **父 agent 的线索 2 是对的**：`_SHARED_POLICIES[stage]["initiative"]` 里那句
> 「不主动开启新话题，不为延长对话而反问」**确实在线上 prompt 里**。
> 需要注意它**不在** `conversation_lead` 卡里（那张卡线上不存在），
> 而是作为 `stage_execution_card` 的一个 JSON 字段发出。
>
> **第 5 处**在 `topicSlot.playerAnchor`，只在槽位触发时出现（= 有历史时），
> 首轮看不到它 —— 详见 **§7.3**。

## 3. 改了什么

### 3.1 阶段话题池：抽象元类目 → 具体物（`data/personas/sve.json`，7 个阶段全改）

判据用 `stage_policy._facet_of_topic`（与硬槽位同一套判据）。**改前的关键事实**：
close / dating 两档**一条都落不到生活面**，parent 只落 1 面——硬槽位（按面禁）
永远指定不了它们，模型只能自由填充内容。

| 阶段 | 改前 | 改后 | 覆盖面 |
|---|---|---|---|
| stranger | 天气／葡萄园工作 | 镇上今天的天气／葡萄园里今天要忙的活／早上烤的那炉面包 | 2 → **3** |
| acquaintance | 酿造／角色扮演／小镇活动 | 想吃的那份香橙鸡／电视上在追的那部《学校女巫》／工作室里那批洒水器的工作 | 2 → **3** |
| friend | 创作计划／家人近况／葡萄园烦恼 | 艾米丽给的那块高级布料／斯嘉丽这位朋友下次来的日子／镇上广场上今天谁在吵 | 2 → **3** |
| close | 未来计划／恐惧与期待／共同经历 | 一个人待着时那种说不清的孤独／记得刚搬来那阵子一起忙的那些天／酿造蓝月亮招牌酒用的那味原料 | **0 → 3** |
| dating | 约会安排／**作品与礼物**／对未来的想象 | 想留给你喝的那瓶蓝月亮／想送你的那块新布料／窝在毯子里一起看电视 | **0 → 3** |
| married | 共同生活／葡萄园计划／彼此的压力 | 今晚一起窝在毯子里的电视／睡前想喝的那杯热巧克力／镇上展览会上我们要摆的那几瓶 | 2 → **3** |
| parent | 孩子与家庭／安全的日常／如何保留个人空间 | 睡前留给自己的一点电视时间／带孩子们去镇上公园玩／发出滑稽声音逗孩子笑的小把戏 | 1 → **3** |

每条都能追到她的真语料（例：「想吃的那份香橙鸡」← `Sat2`「我太喜欢吃香橙鸡了」；
「艾米丽给的那块高级布料」← `Tue6`；「睡前想喝的那杯热巧克力」← `winter_Sophia`）。
**「画了眼线」那条未动**（它在索引 `voiceAnchors` 里，不在 persona 文件）。

### 3.2 「找话题」的矛盾指令：把「回答」改成「起头」（`bridge/src/stardew_ai_bridge/prompts.py`）

意图**保住了**，改的只是"这一轮要做什么"：

| 位置 | 改法 |
|---|---|
| `stage_execution_payload`（非自然路径） | `topic_request` 时**只覆盖** `initiative` 与 `responseShape` 两个字段为「起头」版；`boundaryMode`/`selfDisclosure`/`eventGate`/称呼原样保留 |
| `_stage_execution_instruction` | 非自然路径 + topic 时走独立返回段：去掉「直接接住玩家的意思」「表达预算：直接回答后…」，改成「没有玩家输入可以接住…表达预算：起头之后最多追加一个角色化动作」 |
| 同上 · stranger 专项 | 去掉与「找话题」冲突的「不得…**主动换题**」和预设问题的「问题回答完就停下」，保留「不反问、不邀约、简短」 |
| `_build_turn_plan` | 非自然 + topic 新增分支：`turn_plan.mode` 仍是 `answer_plus_lead`（保留"留一个口子"），文案由「先回答」改成「本轮由 NPC 主动开场」 |
| `_natural_stage_execution_payload`（评测路径） | 同样给出 topic 专用的 `responseShape`（该路径原先硬编码「先直接回答当前输入」，与 `turn_plan` 的「自然开场」互斥） |

**设计取舍**：没有去删 `_SHARED_POLICIES` 里那句「不主动开启新话题」——它是**阶段边界**的
正确表达（不熟的 NPC 不该主动套近乎），删掉会伤到 chat 路径。
改为在 prompt 组装层按 `topic_request` 覆盖：**起头本身不算越界，但仍不追问、不邀约、不安排**。
chat 路径经对照验证**一字未变**。

### 3.3 「文艺腔」与句式模板（同一份契约）

| 改前 | 改后 | 依据 |
|---|---|---|
| ✓ 例「…收进来，**上面还带着太阳的温度**。你要不要帮我叠一半？」 | 「…收进来，**还热乎着**。你要不要帮我叠一半？」 | 示例示范了抒情修饰，被全角色照抄 |
| — | 新增：「示例只示范步骤，**不要模仿其中的比喻、温度、光线、气味或‘好看’‘顺眼’这类审美评价**」 | 只压"修饰"，不压角色本来怎么说自己的事 |
| 「必须有一句来源句，用**‘我刚把…’‘我最近在…’‘刚才看到…’**说清」 | 「必须有一句来源句，说清它是从哪来的（比如刚做了什么、最近在弄什么、刚才看到了什么）；**起手式每轮自然变化，不要反复用同一个开头**」 | 三个模板并列 → 模型把第一个当默认开头（实测 10/12 轮「我刚把…」） |

## 4. `voiceAnchors` 评估（**只报告，未改**）

**父 agent 的假设需要修正一半。**

**事实**：索引静态卡 `voiceCards[Sophia].voiceAnchors` 确实是那 6 条认生期台词
（`Mon`「呃……你好。你需要点什么吗？」/ `Tue`「你，你想要干什么？」/ `Wed` / `Thu`「我今天感觉不太好…」/
`Fri`「我想今天看起来漂亮点，所以画了眼线」/ `Sun`）。
**但它们不是"任何关系下都在教模型模仿"**——`speech.select_stage_voice_anchors`（四级回退：
精确阶段 → 更早阶段 → 无条件日常 → stranger 原文）**按阶段筛过**。逐阶段实测实际进 prompt 的锚点：

| 阶段 | 实际进 prompt 的锚点 | 条数 |
|---|---|---|
| **stranger** | **Fri「…所以画了眼线」（medium）**／Mon「呃……你好。你需要点什么吗？」／Tue「你，你想要干什么？」／Wed「你有过完全没有动力的日子吗？」 | 4 |
| acquaintance | Fri2／Sat2「我希望格斯有卖香橙鸡」／Mon4「如果你需要洒水器…」／Tue2「你最近跟艾米丽和海莉有聊过天吗」 | 4 |
| **friend** | Thu6「你的衣服穿在你身上很好看。那是什么面料的？」／Tue6「艾米丽很贴心，给了我一些她的高级布料」 | **2（两条都是布料）** |
| close | Mon8／Mon10「我想找个时间去爬山…」／Sun8／Tue10 | 4 |
| dating | Mon8／Mon10／Sun8／Thu6 | 4 |
| married / parent | OneKid_2／TwoKids_2／Indoor_Day_Sophia／Indoor_Night_Sophia | 4（**parent 借用 married**） |

**结论（第二轮实测后修正）**：

1. 「**要不要按阶段分**」——**不需要**，机制已经在做。dating/married 拿到的是阶段专属键，不是认生期台词。
2. ⚠ **对上一版结论的一处纠正**：「画了眼线」的 `voiceEnergy` 实测是 **medium，不是 high**
   （`voice_card` 里标着 `[Fri/medium]`）。它是 stranger 档 4 条里唯一的中能量句，
   但**不是"唯一高能量句"**——那 4 条里一条 high 都没有。
3. 🔴 **friend 的硬事实**：索引里 Sophia 的 `friend` 阶段原文**总共只有 2 条**
   （`Thu6`、`Tue6`），不是"选了 2 条"，是**只有 2 条**。
   所以"补几条**同阶段**的锚点"在数据层**做不到**——没有可补的同阶段原话。
4. 🟠 **stranger 的硬事实**：那 4 条里 3 条是戒备/寡言句（「你需要点什么吗」
   「你想要干什么」「你有过完全没有动力的日子吗」），第 4 条才是「画了眼线」。
   **即：stranger 档缺的不是"换掉画了眼线"，而是缺一条不戒备的日常句。**
5. **试过的修法（已回退，未保留）**：把 `select_stage_voice_anchors` 的**整级回退**
   （`if not candidates`）改成**候选不足时补足**（从无阶段标注的日常样本里补），
   这样 friend 2 条 → 补足、stranger 4 条 → 补足，两处一起解决、且是通用规则。
   **实测对她无效**：Sophia 的 weekday 键**全部带阶段标注**，
   "无阶段标注的日常样本"这个来源对她**是空的**（补足后 stranger 仍是 4 条、friend 仍是 2 条）。
   更糟的是第一版没加闸时补进来的是**事件对白**（sourceKey 形如
   `3691380/f Scarlett 125/t 600 1800/…`），即她**在事件里对别人**说的话
   （「加油，斯嘉丽！」「今天早上斯嘉丽开着她爸爸的车来到这里」），
   把 stranger 的 4 条锚点挤掉了 3 条——**比修之前更差**。
   加闸（只接受 `_anchor_category != "other"`）后行为与本轮修改前**完全一致**，
   但它会改变**其他**角色的锚点（未被本轮验证），因此**回退，不留**。
6. **两条待你拍板的路**（都需要动"行为/数据"，不是措辞层）：
   - **A（数据层，窄）**：给索引补 stranger／friend 阶段的高能量日常样本。
     只影响 Sophia，可归因。
   - **B（行为层，宽）**：让候选不足时**从更早阶段借用**（friend 借 acquaintance 的 8 条）。
     friend 2 → 10 条，能立刻解决"两条都是布料"；但**所有角色所有阶段**的锚点都会变多
     （上限 `_STAGE_VOICE_ANCHOR_MAX_COUNT = 8`），prompt 变大、声线来源变杂，需要单独一轮验证。
   - ❌ **不建议**在排序里"同等能量下避开角色专属爱好"：`画了眼线` 命中
     `_LIFE_FACET_PATTERNS` 的「工作或手艺」面（含「画」字），
     按面排后等于把她唯一不戒备的那句排到最后，而把 3 条戒备句顶上去——
     方向与"贴角色"相反。
7. parent 借用 married 的锚点（含"孩子"的对白）语义上可接受。

## 7. 第二轮：话题池改法到底有没有用（同形状复跑）

### 7.1 落面分布对照

同形状（stranger/acquaintance/friend/dating × 连点 3 次，空消息 + topic + 紧凑 + 无 seed），
判据 `stage_policy._facet_hits`（一条回复命中多面就都计，所以百分比之和 >100%）：

| 指标 | 改前 `cloud-run-…215342` | 改后 `cloud-run-…221015` | 变化 |
|---|---|---|---|
| 请求 / tokens | 12 / 142,568 | 12 / 144,200 | — |
| 最大单一生活面占比 | 工作或手艺 **6/12 = 50%** | 工作或手艺 **7/12 = 58%** | ❌ **未改善** |
| 「无面」（判不出任何生活面） | **4/12 = 33%** | **1/12 = 8%** | ✅ 明显改善 |
| 不同生活面数 | 4 | **5** | ✅ 略增 |
| 出现的面 | 工作或手艺 / 天气季节 / 过去的回忆 / 镇上或邻里 | 上述 + **吃喝** | ✅ |

**诚实结论**：
- 话题池换成具体物**确实让话题变得更"可归类"**（无面 33% → 8%），面数从 4 增到 5，
  新的面（吃喝：桦树糖浆爆米花、热巧克力）**确实被说出来过**；
- 但**最大集中面没有降**（50% → 58%）。**话题池不是落面集中的主因。**

### 7.2 真正的主因：轮换槽位的**触发阈值**，不是话题池

云端批次里逐轮检查 `stage_execution_card.topicSlot`：

| 阶段 | t1 | t2 | t3 |
|---|---|---|---|
| stranger | 无 | 无 | ✅ **触发**（`facetRepeat`，禁「工作或手艺」→ 建议「过去的回忆」） |
| acquaintance | 无 | 无 | 无 |
| friend | 无 | 无 | 无 |
| dating | 无 | 无 | ✅ **触发**（同上） |

- **槽位触发时是有效的**：两处触发后，那一轮的回复**真的换到了「过去的回忆」**
  （"…我刚搬来鹈鹕镇那阵子住过一间旧房子，窗户关不严，风一吹就吱呀响…"）。
- **acquaintance / friend 没触发**，原因是阈值够不到：
  `_FACET_LOOKBACK = 3` + `_FACET_REPEAT_THRESHOLD = 2`（最近 3 轮里同一面出现 ≥2 次）。
  - acquaintance 实际是「工作 → 吃喝 → 工作」：t3 时窗口内工作面只出现 **1** 次；
  - friend 实际是「工作 → **无面** → 工作」：中间那轮判不出面，同样只算 **1** 次。
- 也就是说：**"她在两面之间摇摆"和"中间一轮判不出面"这两种形状，正好绕过阈值**，
  而它们恰恰是持续塌缩时段最常见的形状。

**这是本轮查出的、比话题池更根本的一处**（`stage_policy.py` 的
`_FACET_LOOKBACK` / `_FACET_REPEAT_THRESHOLD`）。**未改**——它是全局行为参数
（影响所有角色所有路径），改它需要单独一轮验证 + 你的拍板。

### 7.3 第五处同型矛盾（已修）

槽位触发时才暴露的：`topicSlot.playerAnchor` 写的是
「硬约束：**玩家本轮点名**的对象必须先接住、先应下来」——
topic 路径**同样没有本轮玩家输入**（槽位只在有历史时才产出，所以首轮看不到它）。
槽位自己的 `instruction` 说的是「先接住那里面的具体东西」（= **上一轮她说过的话**，
topic 下有历史、成立），所以只摘掉 `playerAnchor`，`bannedFacet` / `suggestedTopic` /
`instruction` 全部保留。chat 路径的 `playerAnchor` **原样保留**（有回归钉住）。

## 9. 两处判断错误（**保留记录**：探针口径错了会得出反向结论）

本轮排查中途，我基于**错误的探针口径**下过两个结论，事后都被推翻。
记在这里，因为它比结论本身更值得复述：

| 我的错误结论 | 为什么会得出 | 事实 |
|---|---|---|
| 「`{topicPool}` 在游戏端从来不进 prompt」 | 用 `scripts/run_character_quality_eval.py` 的 `_build_context` 做探针 —— 它给 adaptive 案例注入 **`naturalMode=True`**，于是 `conversation_lead` 卡的条件判断走了**评测分支** | 游戏端那条卡确实不生成，但 `{topicPool}` 作为 **`stage_execution_card.conversationLead.roleGuidance` 的字段**照旧发出 |
| 「『不主动开启新话题』不进 prompt，父 agent 的线索 2 不成立」 | 同一原因：`naturalMode=True` 让 `_natural_stage_execution_payload` **pop 掉了 `initiative`** | 游戏端请求体（`BridgeDialogueRequest`）**不带 `qualityContext`** → `naturalMode` 不是 True → 走 `_compact_stage_policy` 分支 → **那个字段在线上 prompt 里** |

**教训**：
1. **探针必须走真实入口**。线上是 `app._build_context`（= `/api/context/preview`），
   不是评测 runner —— 两者注入的 `qualityContext` 不同，会走到**不同的卡片分支**
   （评测路径多出 `sophia_liveliness_final`、`natural_topic_role_override` 等 4 张卡）。
2. **"某句话不在 prompt 里"这种否定结论，必须逐卡定位**（本轮的
   `.tmp/topic-probe/locate.py` 就是干这个的），不能靠"搜一遍没看到"。

## 12. 「无面」轮次诊断（用户要求的第二种结论判定）

两批云端共 **5 轮无面**，逐条判：

| 批次 | 轮次 | 她说的（关键片段） | 判定 |
|---|---|---|---|
| 改前 | stranger t2 | 「这是我刚装瓶的**苹果酒**，尝了一口酸得我直皱脸」 | **具体物 · 词表缺口** |
| 改前 | acquaintance t2 | 「我刚把最后几瓶**封好蜡**……这批的**颜色**比上一批深很多」 | **具体物 · 词表缺口** |
| 改前 | friend t2 | 「我刚刚在**贴标签**……这一批的**红**比上一批好看」 | **具体物 · 词表缺口** |
| 改前 | friend t3 | 「我刚把最后几瓶封好，手指上全是**木塞**的味道」 | **具体物 · 词表缺口**（我的初版分类器漏判） |
| 改后 | friend t2 | 「那批**白葡萄**……那瓶**发酵**得不太顺的……搬到了**桶架**下面那格」 | **具体物 · 词表缺口** |

### 结论：**5 / 5 全部是「具体物但词表没收录」，0 条是「她什么实质都没说」**

**所以阈值不该按"她本来就没说什么可归类的东西"来调** —— 判据本身是对的，
**是词表判不出**。缺的词（逐条从原句提取）：

| 缺词 | 现状 | 该落在哪一面 |
|---|---|---|
| **酒**（"苹果酒"） | 吃喝面只有 `酒馆`/`酒吧`，**没有"酒"** | 待定（见下） |
| **标签** | 工作面没有 | 工作或手艺 |
| **葡萄**（"白葡萄"） | 只有 `葡萄园` | 工作或手艺 |
| **发酵** | 没有 | 工作或手艺 |
| **桶**（"桶架"） | 只有 `酒桶` | 工作或手艺 |
| **塞 / 木塞** | 没有 | 工作或手艺 |
| **封蜡 / 蜡** | 没有 | 工作或手艺 |

⚠ **落地前必须注意**：这些词里 **「酒」「葡萄」极宽**（她几乎每轮都说），
