# Victor 试点与全库文风对齐：前后对照实验（2026-09-26）

## 结论先行

1. **「贴近原版文风 = 扣语气字」是错配。** 语气字这一层的 prompt 已经压到设计上限 ——
   `voice_execution_card` 明写「speechParticles 只是低优先级的可选口语颗粒参考，**默认不用**，
   一组三轮对话最多自然使用一次」。继续往这个字段投，是白名单里额度最小的一项（4 条 × 12 字）。
2. **提示的形态决定成败：动作描述有效，数字锚点反效果。**
   句长锚点写「一句话通常十来个字」→ 句长 **13.0 → 16.5**（更长）；
   改写成「一句话一个意思，说完就停…」→ 句长回落 **13.5**、逗号/句 **0.42（六组最低）**。

   > ⚠ **2026-09-26 更正：这一条的效应量不足以支撑结论。**
   > 全库推广的三组对照（`docs/report-sentence-length-noise-2026-09-26.md`）显示
   > **组内三轮极差 13~32 字，远大于组间均值差 1~3 字** ——
   > 本条 13.0 vs 16.5 的 3.5 字差异同样落在噪声里。
   > 句长若还要继续调，先按那份报告 §七 标定信噪比（同版本多组重复），再谈版本对比。
3. **感叹号缺口在模型层，不在 prompt 层** —— 我的「人设内部矛盾」假说被自己的实验证伪（详见 §3）。
4. **全库清点出 7 条「不用感叹」禁令，而 36/44 个角色的原文感叹号率 ≥15%**（Vincent 68.6%）。
   全部集中在 `signatureMoves`，措辞高度雷同 —— 人设是手工写的，不是从原文挖的。
5. **44 个角色的语气字已 100% 对齐原文**，凭空写的字清零（`--audit` 复核通过）。

## 一、六组对照数据

入口 `stardew_ai_bridge.app._build_context(compact_prompt=True)`（游戏端真实入口）；
Victor / friend / 4 心 / `channel=remote`；固定 3 轮玩家台词。

| 组 | 句长均值 | 逗号/句 | 感叹号 | 省略号 | 字数 | tokens |
|---|---:|---:|---:|---:|---:|---:|
| before（原始） | 12.31 | 0.44 | 0 | 3 | 127 | 8 054 |
| before② | 13.75 | 0.75 | 0 | 3 | 183 | 8 155 |
| after（数字锚点） | 16.47 | 0.89 | 0 | 9 | 154 | 8 190 |
| after②（数字锚点） | 14.72 | 0.64 | 0 | 9 | 252 | 8 217 |
| action（动作锚点） | 16.50 | 0.50 | 0 | 6 | 128 | 8 144 |
| **noconflict（动作锚点 + 去掉禁令）** | **13.50** | **0.42** | 0 | 6 | 177 | 8 208 |

原文基准：Victor 句长中位 **11**、感叹号率 **33.0%**、省略号率 26.4%。

**读法**：noconflict 的逗号密度是六组最低、句长最接近原文 —— 这是「动作描述 + 清掉反向指令」
的合力。`tone` 里「近三成的话带省略号」稳定生效（3 → 6~9，两组一致）。
⚠ 每组 n=3，只支持方向不支持定论。

## 二、发现 ①：动作锚点有效，数字锚点反效果

- **数字锚点**（「一句话通常十来个字，最多二十出头」）：模型不按数字控长，句长反而从 13.0 涨到 16.5。
- **动作锚点**（「一句话一个意思，说完就停；不要把几个意思用逗号串成一句，也不要用破折号拖长」）：
  配合清掉禁令后，逗号/句降到 **0.42**（低于原始组的 0.44/0.75），句长回到 13.5。
- 结论：**写「怎么做」而不是「多长」**。这与项目此前 §44/§52 的经验一致。

## 三、发现 ②：感叹号缺口 —— 假说被自己的实验证伪

**我原来的判断**：`tone` 写「常带感叹号」但 `signatureMoves` 写「不用感叹撑场面」，
两条都进 prompt，模型听了更具体的后者 ⇒ 禁令吃掉了正向提示。

**实验**：`noconflict` 档把那条禁令删掉（保留 `tone` 的正向提示 + openers 里 2 句带感叹号的真实原话），
结果 —— **感叹号仍然 0**。

**零成本结构探针的证词**（`.tmp/victor-prompt-check.py`，不花云端请求）：
全 prompt 20 张卡、9 303 字符里，出现「感叹」的句子只有 **2 处，且都是我自己加的正向提示**；
全角 `！` 字符只出现 **2 次**（在我塞进 openers 的原话里）。**prompt 里根本没有任何压制感叹号的东西。**

⇒ 修正后的结论：**感叹号率 ≈ 0 是模型层的输出倾向**，不是 prompt 结构问题。
旁证：`docs/report-style-compare-2026-09-24.md` 里 DeepSeek 与 Kimi **两个模型都是 ~0.00**，
而原版 0.31–4.25 —— 跨模型一致，说明是通用倾向。

**这一条需要你决策**：原文（中文翻译）的感叹号率 15%~68%，很可能是**英文对白风格的残留**。
要不要为了「像原文」而在出口层补感叹号，是一个文风取向的判断题，不只是技术题。

## 八、方法与坑（留给下一次）

1. **pwsh 控制台是 GBK，会不可逆地毁掉中文管道输出** —— 跑 Python 前必须
   `$env:PYTHONIOENCODING='utf-8'`，要看中文一律 `read` Python **自己写的** UTF-8 文件。
   `--audit` 第一次就崩在 `⚠`(U+26A0) 上（`UnicodeEncodeError`），**exit=1 是编码崩溃不是审计失败**。
2. **`data/personas/*.json` 不能用 JSON 往返重写** —— 三个文件都无法 byte-identical 还原，
   会产出整文件 diff。用文本级「值区间」替换，并断言「语义差异仅目标字段」。
3. **改人设不需要重载 Bridge**（探针直连 provider、逐进程重读文件）；但**游戏内**要生效必须重载。
4. **`gamereal_probe.py` 的 `payload()` 把 npcId/displayName 写死成 Sophia**，`--npc` 进不了请求体。
5. 自查：跑 pytest 要带 `PYTHONPATH=<worktree>\bridge\src;<worktree>\scripts`，否则收集期就报
   `ModuleNotFoundError`（exit=2），看着像失败其实没跑。
