# 中文角色扮演模型候选与评估

日期：2026-08-30  
研究问题：中文社区是否存在值得用于本项目的角色扮演模型。  
范围：公开 Hugging Face 模型卡、量化仓库元数据和公开中文 RP 讨论入口；不下载模型、不发送项目资料、不使用任何密钥。  
目标场景：中文、短句、日常、多轮、关系阶段明确的《星露谷物语》NPC 对话。

## 结论

中文 RP 模型确实有人做，但公开生态明显小于英文 RP 生态，而且“仓库标注 zh/中文”不能直接证明中文自然或角色贴合。当前最值得做本地对照的是：

1. **首测：`Peach-2.0-9B-8k-Roleplay`**。模型卡明确写明使用中英双语数据、SFT+DPO、训练长度 8K，并声称改善上下文重复和逻辑错误；Q4_K_M 量化约 5.33 GB，适合当前机器单独测试。它仍是偏通用长篇 RP 模型，不是 Stardew 专用模型。
2. **保留基准：本地 `qwen3.5:9b`**。它不是 RP 微调模型，但中文基础能力、当前 Bridge 接入和速度已经有实测，应该作为同条件控制组，不应因为 RP 标签就直接替换。
3. **中文 API 首测：阿里云 `qwen-plus-character`**。它是目前定位最贴近“中文游戏 NPC/角色复刻”的商业候选；但这属于官方产品定位，不等于独立社区质量排名，仍需与本地 Qwen 做盲测。
4. **观察候选：`ArityFlow-Qwen3-4B-Instruct-2507-RolePlay`**。它有实际模型文件并标注中英，但公开使用量较低，不能排在 Peach 之前。
5. **暂不采用：`Qwen3-4B-RPG-Roleplay-V2`、`Collective Chinese Roleplay 8B`、`Qwen2.5-14B-roleplay-zh`、`vanilla-cn-roleplay-0.2`**。它们分别存在英文数据偏重、社区使用证据弱、超出当前硬件或训练题材偏言情等问题。

## 公开证据

### 1. 最值得先测：Peach 2.0

`ClosedCharacter/Peach-2.0-9B-8k-Roleplay` 的中文 README 声明：

- 基于 Yi-1.5-9B；使用超过 100K 轮对话进行 SFT，并经过 DPO；
- 使用中英双语数据；训练最大长度为 8K；
- 目标包括剧情推进、话题拉扯，以及减少上下文重复和逻辑错误；
- README 同时明确提示 9B 模型可能产生幻觉，建议降低 temperature/top_p，并提示可能生成 NSFW 内容。

公开使用信号不是质量证明，但可以作为筛选参考：原始仓库当前约 225 次下载、87 个赞；`mradermacher` 的 GGUF 量化仓库约 2,239 次下载、9 个赞。Q4_K_M 文件约 5.33 GB，和旧版 Peach 9B 体积基本相同。

**推断：**它比“名字带 Chinese、但没有权重或几乎无人使用”的候选更值得安排第一轮实验；但它训练目标仍是长篇/沉浸式 RP，可能出现戏剧化、动作描写和过长回答，与 Stardew 的短句日常风格存在冲突。

### 2. 有使用量但不是中文模型：Qwen3-4B RPG Roleplay V2

`Chun121/Qwen3-4B-RPG-Roleplay-V2` 当前约 17,627 次下载、71 个赞，公开使用信号强于多数中文候选；但模型卡语言标为 `en`，训练集是 `Gryphe/Sonnet3.5-Charcard-Roleplay`，并明确包含 NSFW/成熟题材。

**判断：**它可以作为轻量英文 RP 参考，不能当作中文 Stardew NPC 首选。它有可能帮助模型遵守角色卡，但不能解决中文口语、星露谷原版短对白和角色阶段边界。

## 为什么“中文 RP 模型”仍不一定适合本项目

中文 RP 社区常见的优化目标，通常是长篇沉浸、动作描写、恋爱推进或成人内容；本项目真正需要的是另一组能力：

- 一两句自然、带角色口头习惯的中文，而不是小说段落；
- Shane 初识阶段可以冷淡、结束聊天，其他角色也要按关系阶段改变主动性；
- 远程聊天与面对面聊天分开，邀约要能在线上提出、在线下继续；
- 连续点“找话题”必须承接上一个具体对象，不机械回扣同一件事；
- 未发生的事件、未确认的记忆和不属于角色的魔法知识不能被模型自行补齐。

因此，RP 微调最多解决“愿意进入角色、少一点助手腔”的一部分问题，不能替代当前项目的原版对白筛选、行为卡、阶段策略、渠道投影和人工审核。

## 给本项目的推荐实验

暂不一次下载多个模型。下一轮只做一个可恢复的对照：

1. 下载 `Peach-2.0-9B-8k-Roleplay` 的 Q4_K_M GGUF，单独导入隔离 Ollama，不覆盖当前 `qwen3.5:9b`。
2. 使用同一份中文联合索引、同一份行为卡、同一组 15 个固定质量案例、同一段历史和相同输出上限。
3. 记录实际模型名、provider、fallback、耗时、输出长度和原始回复；不把 Peach 的回复写回 `behavior-examples.json`，不把未经人工审核的结果变成角色资料。
4. 人工只比较五项：星露谷原文感、角色辨识度、中文自然度、关系/渠道正确性、上下文承接。
5. 如果 Peach 只表现为更长、更戏剧化，或者中文口语没有稳定提升，就保留 Qwen 作为默认，把精力继续放在条件检索和行为阶段策略，而不是继续换模型。

## 限制

- 下载量、点赞数和量化仓库下载量只是公开使用信号，不是中文质量排行榜，也不代表模型在 SillyTavern 之外的真实使用情况。
- 本轮没有下载这些候选，也没有用项目固定题集实际生成回复，因此不能声称 Peach 或任何候选已经胜过 `qwen3.5:9b`。
- 模型卡中的“最佳”“高质量”等是作者自述；最终选择必须依靠同条件 A/B 和人工盲评。
- Hugging Face 元数据、模型文件和社区活跃度会变化；真正下载前需重新检查文件、许可证、模板和本地磁盘空间。
