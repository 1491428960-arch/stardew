# 线上—线下未完事项闭环实现计划

> **面向 AI 代理的工作者：** 使用 `executing-plans`（紧密耦合的跨 C# / Python 任务）逐任务实现。每个任务先写并运行失败测试，再写最小实现；保留既有未提交修改，不创建 Git commit。

**目标：** 让线上聊天可以留下当前 NPC 专属的未完事项，并让下一次面对面 AI 对话在收到明确结构化信号后承接或关闭该事项。

**架构：** C# `StoryStateStore` 持有独立 `OpenLoopRecord` 集合，`ConversationService` 根据当前渠道消费 Bridge 的 `OpenLoopSignal`。Bridge 只在模型/适配器提供顶层 `openLoop` 时转发结构化元数据，并通过现有关系世界投影把活动事项限制在当前 NPC 视角内。普通文本、fallback 和失败不参与状态迁移。

**技术栈：** C# / .NET 8 测试项目、SMAPI Mod 类型、Python 3.10+、FastAPI、Pydantic、pytest、现有 Bridge Provider 和 PromptBuilder。
