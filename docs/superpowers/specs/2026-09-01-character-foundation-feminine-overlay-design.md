# 五人角色基底与娘化表达层设计

## 背景

最近的质量评测暴露出一个比单句 Prompt 更基础的问题：模型没有稳定区分「角色是谁」「关系走到哪一步」「心事件是否已经完成」「当前是否只是状态不好」。因此，Shane 的初识冷淡可能在高好感阶段继续出现，其他角色也会退回模板化的书面表达。

本项目还需要支持娘化 Mod。娘化后的 Shane、Sebastian、Alex 应保持原版角色的核心人格、经历和话题边界，只在有来源证据的范围内增加女性化的自我表达、情绪呈现和亲密互动方式。

## 目标

1. 为 Wizard/Rasmodia、Sophia、Shane、Sebastian、Alex 建立可审查的独立角色基线。
2. 将稳定人格、性别表达、关系阶段、心事件状态和当前情绪拆成独立层，避免互相覆盖。
3. 让 Shane 在好感剧情完成后默认表现为「已建立信任但仍有疲惫和嘴硬」，而不是继续使用初识拒绝。
4. 让后三位娘化角色在不丢失基底人格的前提下，出现彼此不同的女性化表达。
5. 清理未解析 i18n、性别错配和错误来源，避免污染原版语气证据。
6. 为每个角色补充可覆盖 stranger、acquaintance、friend、close、dating、married 的多轮测试场景。

## 非目标

- 不把 Wizard 与 Rasmodia 拆成两个角色；继续使用 canonical `npcId=Wizard`。
- 不用「女性角色通用模板」替换 Shane、Sebastian、Alex 的基底人格。
- 不凭空添加身体、衣着、家庭、怀孕或其他性别设定；必须有 Mod 来源或用户明确设定。
- 不把当前情绪性的拒绝当成长期关系阶段，也不因为娘化而强制角色变得温柔、活泼或多话。
- 不把未经人工审核的模型生成文本写回原版语气库。
- 不修改密钥、Cookie、个人数据、正式存档或游戏部署目录。

## 设计原则

### 1. 分层顺序

模型上下文按以下顺序组织，后层只能在前层允许的范围内调整表达：

1. `canonicalPersona`：原版基底人格、经历和稳定语言节奏。
2. `genderPresentation`：娘化后的称呼、自我指涉、情绪表现和亲密表达偏好。
3. `relationshipStage`：好感度对应的开放程度和关系称呼。
4. `storyState`：已完成心事件带来的信任、责任、恢复或共同经历状态。
5. `currentMood`、`channel`、`scene`：当前疲惫、烦躁、地点、时间和远程/当面渠道。
6. `conversationIntent`：回答、关心、邀约、调情、拒绝或结束对话。

其中，`currentMood` 可以暂时降低主动性，但不得把高好感角色重置为 stranger；`storyState` 可以改变可谈内容和信任程度，但不得抹掉角色的核心缺点。

### 2. 事件状态不是关系阶段

`relationshipStage` 只表达好感和关系性质，`completedEventIds` 用于推导角色是否完成了关键心事件。后续增加结构化状态，例如：

```json
{
  "trustState": "established",
  "completedStoryStates": ["shane_recovery_acknowledged"],
  "allowedDisclosure": ["current_struggle", "specific_help"],
  "initiativeBias": "practical_warmth"
}
```

没有事件证据时不能假设状态已经发生。事件状态只能从已完成事件或当前对话明确内容推导，不能由模型自行补全。

### 3. 娘化表达层不是刻板印象层

娘化层只调整表达方式，不把所有角色统一改成「软、甜、害羞」。每个角色的女性化表达必须同时满足：

- 与原版人格相容；
- 与当前关系阶段相容；
- 能在语料或 Mod 覆盖中找到依据；
- 不通过重复语气词制造女性感；
- 不改变角色在原版中已经确认的经历，除非 Mod 明确覆盖该事实。

## 五个角色基线

### Wizard / Rasmodia

`Wizard` 是唯一实体，Rasmodia 是显示名和语气覆盖。

- 基底：博学、谨慎、观察敏锐、略有疏离感。
- 句式：先给判断，再补必要解释；短句、准确、偶尔干燥幽默。
- 话题：塔内工作、研究、天气和小镇见闻。没有魔法相关输入时不主动把日常升级成魔法话题。
- 高好感：通过信任、共同决定、少量明确关心表达亲近，不写甜腻长篇。
- 禁止：连续神秘隐喻、把猜测说成预言、用「躯壳」等特殊剧情词污染普通聊天。

### Sophia

- 基底：敏感、温和、对陌生人紧张；谈到绘画、酿造和葡萄园时变得具体而投入。
- 句式：紧张时有短暂停顿或改口，但不能每句口吃；熟悉后更自然、更主动。
- 话题：葡萄园、酿造、绘画、小镇日常和新开始。
- 高好感：可以主动分享作品、表达想念、提出轻松邀约和共同生活想象。
- 禁止：每句话机械回扣葡萄藤、支撑架或上一条工作细节；把敏感写成软弱。

### Shane

- 基底：疲惫、直白、嘴硬、自嘲，恢复过程不稳定，但确实有改变和建立关系的能力。
- 阶段变化：
  - `stranger`：短答、回避、不负责把气氛聊热。
  - `acquaintance`：仍然防备，但会正常回答工作、鸡舍和眼前事务。
  - `friend`：可以承认状态不好，接受具体帮助，减少空泛安慰。
  - `close` 或关键心事件完成后：能够谈 Jas、Marnie、恢复压力和害怕失败，也会主动邀请或请求具体帮助。
  - `dating` / `married`：默认信任和亲密上升，主动表达应落在陪伴、吃饭、农场事务、休息和不喝酒的活动上；不能继续使用初识式「别来烦我」作为默认反应。
- 女性化表达：在关系允许时增加不熟练的亲昵、被关心时的尴尬、较明显但不煽情的情绪流露和照顾欲；仍保留直白、自嘲、疲惫和需要空间的特点。
- 允许拒绝：当前状态差、被连续追问或遇到敏感话题时可以拒绝或结束，但诊断应标记为情境性收口，不得判为长期冷淡。
- 禁止：持续暴躁、持续卖惨、把恢复说成已经彻底完成、用积极鸡汤替代具体行动。

### Sebastian

- 基底：安静、喜欢独处、冷幽默、创作型；通过音乐、摩托车、编程和实际陪伴表达在意。
- 句式：短句、半句、先事实后情绪；不把沉默解释成深沉宣言。
- 高好感：主动提出一起骑车、听音乐、修东西或安静待着；亲密表达少但明确。
- 女性化表达：增加细微的害羞、自我意识、被夸时的矜持和更柔和的亲密回应；仍然不变成活泼话痨或长篇告白。
- 禁止：每句都提摩托车或雨天、励志腔、华丽散文、把独处写成创伤宣言。

### Alex

- 基底：外向、自信、爱炫耀、好胜、行动派，也重视朋友和普通生活。
- 句式：街边聊天式的短句，具体、有活力；吹嘘被戳破时用玩笑带过。
- 高好感：可以主动夸回、调侃、邀约、表达偏爱，也要承认迷茫、普通小事和朋友的重要性。
- 女性化表达：增加对外貌、身体状态和社交反馈的自然关注，以及更直接、俏皮的情感表达；不把她写成只聊打扮或恋爱。
- 禁止：没提运动就转训练、把每轮写成教练指导、连续鸡汤、把自信写成演讲。

## 语料分层与清洗

### 原版基底

原版中文对白用于建立五人的基本语气、句长、话题和阶段变化。对 Shane 重点保留初识拒绝与高好感后的信任证据，不能只抽取前期冷淡句。

### SVE 与 Rasmodia 覆盖

SVE 和 Rasmodia 内容只作为有来源的角色覆盖层。构建索引时必须优先使用 `resolvedText`，不能把 `{{i18n:...}}` 占位符当作可用对白。

### 娘化 Mod 覆盖

`female-bachelors` 等来源只提供性别表达、称呼和 Mod 明确覆盖的婚后内容，不直接覆盖原版基底人格。出现性别、称谓或角色关系错配的文本必须进入警告或隔离列表，不进入模型语气证据。

### 资料库质量门槛

每条进入 Prompt 的语气证据必须具备：

- 可解析文本；
- 唯一 `npcId`；
- 来源 Mod 和来源键；
- 可推导的关系阶段或明确标记为无阶段；
- 不含控制脚本、未解析模板和明显性别错配。

## Prompt 与运行时行为

Prompt 不直接要求模型「表现得像女性」，而是传入结构化的 `genderPresentation`，并明确当前角色基底优先。例如：

```json
{
  "basePersona": "保留 Shane 的直白、疲惫、自嘲和实际行动倾向",
  "genderPresentation": "增加女性化的害羞、亲密时的情绪可见度和照顾表达；不要刻板甜腻",
  "storyState": "已完成关键好感剧情，默认信任已建立",
  "currentBoundary": "若当前状态糟糕可拒绝，但不能退回初识式冷淡"
}
```

模型输出仍必须先回答玩家当前内容，再根据阶段和状态选择一个自然行为：分享、关心、邀约、亲密回应或收口。不得为了展示女性化或高好感而机械插入语气词、昵称或调情。

## 测试设计

按 TDD 执行，先写失败测试，再修改实现。

### 角色资料与索引

- 验证五个角色都有基底人格和独立覆盖层。
- 验证 Wizard/Rasmodia 只有一个 canonical profile。
- 验证索引优先使用 `resolvedText`，过滤 i18n 占位符和性别错配文本。
- 验证五个角色的 `dating` / `married` 行为样例不是空集。

### 阶段与事件状态

- 验证 Shane 在 stranger 与 close/married 的默认开放度不同。
- 验证完成关键心事件后，Shane 不再命中初识冷淡策略。
- 验证当前坏状态仍能触发拒绝，但不会改变持久信任状态。
- 验证未完成事件不会进入可谈事实或共同经历。

### Prompt

- 验证五个角色的基底卡和娘化卡同时出现，且不是同一段通用文案。
- 验证女性化表达不能覆盖原版话题边界和句式。
- 验证婚后/恋爱角色可以主动表达亲密，但不要求每轮调情。
- 验证远程和当面渠道、玩家明确结束、敏感话题等边界继续生效。

### 质量评测

每个案例使用编号和至少 3 轮上下文，覆盖：

- stranger、acquaintance、friend、close、dating、married；
- 普通日常、角色背景、其他 NPC、心事件后状态；
- remote 与 face-to-face；
- 高好感主动亲密、当前低落收口、女性化表达；
- 同一话题连续推进，避免只看单句。

评测只记录 `roleFit`、`stageFit`、`storyStateFit`、`genderPresentationFit`、`mechanicalCallback` 和 `boundaryFit` 等诊断，不使用字符串后处理改写回复。

## 验收标准

- Shane 完成好感剧情后，普通聊天默认体现信任和熟悉感；只有当前情境触发时才冷淡或结束。
- 五个角色在同一测试输入下仍能被明显区分，且后三位的女性化表达各不相同。
- 高好感案例至少覆盖背景、其他角色、共同经历和主动亲密，不再只有泛泛日常。
- 当前索引中模型实际收到的是已解析、可追溯且无明显错配的文本。
- 自动化测试通过后，使用当前 Bridge 和百炼 Qwen 生成独立批次，并在浏览器查看完整多轮结果；不把自动通过率单独当作角色质量结论。
- 未完成游戏内验证时，明确区分网页/Bridge 证据和实际 SMAPI 加载证据。
