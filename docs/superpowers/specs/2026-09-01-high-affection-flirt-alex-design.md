# 高好感多轮调情案例与 Alex 角色质量修正设计

## 背景

当前固定质量评测只有少量 `close` / `married` 案例，且大多数案例是一轮或低强度日常对话。测试页虽然已经能筛选高好感阶段，但无法充分观察关系推进、不同渠道和不同调情尺度。Alex 的现有行为样本又过度集中在训练、目标和行动计划，造成回复像通用励志模板；“职业球员/职业选手”等近义话题也可能让行为检索失配。

本轮要把高好感阶段做成可比较的多轮评测维度，同时修复 Alex 的证据分布与话题匹配。生成结果仍是评测工件，不自动写回角色资料库。

## 目标

1. 为主要可恋爱角色补充高好感多轮案例，覆盖 `close`、`dating`、`married`，并在不同案例之间交错轻度暧昧、中度直白和成人向直白的调情强度。
2. 保持线上与当面聊天的区别；线上邀约只能形成待确认的约定，当面案例才能推进现场互动。
3. 让关系阶段、好感度、剧情进度、角色背景和已知他人真正进入案例与 Prompt，并可在浏览器中按这些条件查看完整对话。
4. 让 Alex 的行为证据包含原版式的自信、嘴硬、竞争式玩笑、朋友亲近感、脆弱处的防御和行动派表达，而不是只包含训练计划。
5. 用专项质量标签识别阶段错配、机械回扣、训练话题过度、通用模板和重复开场；不使用字符串后处理改写模型回复。

## 非目标

- 不把 Wizard 与 Rasmodia 拆成两个实体；继续使用 canonical `npcId=Wizard`，仅保留 Rasmodia 的显示名和语气覆盖。
- 不给不可恋爱 NPC 强行添加恋爱或性内容；他们只增加高好感友情、背景和关系网案例。
- 不改写或覆盖既有评测工件，不把未人工审核的新生成内容写入 `data/personas`。
- 不切换当前 Codex 模型，不替换百炼 Qwen 默认配置，不启动游戏或部署 DLL 作为本轮必要步骤。
- 不通过正则删词、替换语气词或拼接固定句子“修复”自然语言。

## 设计

### 1. 案例模型与矩阵

在 `CharacterQualityCase` / `CharacterQualityTurn` 中增加可选的结构化评测元数据：

- `friendship_hearts`：用于 UI 和评测说明的好感度心数；已有 `game_state.friendshipHearts` 时保持兼容。
- `flirt_intensity`：`none`、`light`、`direct`、`explicit`。`none` 为日常或情感支持，其他三档交错使用，不要求每个案例都有调情。
- `adult_consensual`：只有成人角色、关系阶段足够高且双方明确自愿时才允许 `direct` / `explicit`；缺少该标记时，案例定义校验失败。
- `romance_eligible`：明确案例是否允许恋爱推进；不可恋爱角色只能使用 `false`，并拒绝非 `none` 的调情强度。
- `relationship_context`：简短、可审计的关系变化说明，例如“已确认彼此在约会”“婚后日常”；不能把玩家单方面的邀约写成 NPC 已同意。

第一批以 Rasmodia/Wizard、Sophia、Shane、Sebastian、Alex 为主要角色，每人至少包含：一个高好感日常或背景案例、一个轻/中度暧昧案例、一个成人向直白案例或明确拒绝/收口案例。`married` 只用于角色设定允许的角色；对 Shane 等边界明显的角色保留冷淡、拒绝或结束聊天的有效输出空间。每个案例至少 3 轮，轮次之间有明确可追踪锚点，但不要求每轮重复同一个名词。

调情强度不等于统一文风：关系阶段和角色边界优先于强度。成人向案例只测试成年、双方自愿、关系已建立的上下文，不在陌生或未确认阶段注入露骨内容；测试定义保存约束元数据，结果页显示强度和边界，不在列表中展示密钥或完整 Prompt。

### 2. 渠道与剧情约束

每个高好感案例继续显式声明 `remote` 或 `face_to_face`：

- `remote` 只能是手机/线上消息。可以表达想见面、提出邀约或保留待确认话题，但不能把 NPC 写成已经走到玩家身边、发生现场接触或完成未确认的赴约。
- `face_to_face` 只能是当前同地点的互动，可以承接已确认的线上约定，但不能倒写成手机发消息。
- `history` 和 `turns` 只记录已发生的对话；玩家单方面说“下次一起”时，后续只能标为 `pending_topic` 或待确认邀约，除非 NPC 明确接受。
- `story_progress`、背景故事、NPC 已知角色和当前地点是证据，不是必须逐句复述的关键词。Prompt 要求优先自然回答，禁止为命中证据机械回扣。

### 3. Alex 证据修正

为 Alex 增加审核过的 `human_approved` 成对示例，覆盖：海滩和朋友、过去的四分卫经历、外貌夸奖后的得意与转移、竞争式调侃、嘴硬式关心、轻微吃醋、亲密邀约、失败后的不服输，以及训练之外的普通生活。训练、进步、目标类示例保留但限制在专项主题中，避免成为默认开场。

行为检索增加同义话题归一化/别名匹配，例如“职业球员”“职业选手”归入同一主题；排序仍优先当前角色、关系阶段、渠道和主题，随后才使用通用行为样本。冲突翻译变体不直接混为高置信度证据，保留来源和置信度以便审计。

### 4. 质量评测与结果

质量评测仍按固定案例顺序执行多轮请求，并在每轮记录脱敏元数据。新增专项标签：

- `flirt_stage_mismatch`：调情尺度与关系阶段、角色资格或自愿状态不一致；
- `romance_boundary_violation`：把未确认邀约、拒绝或冷淡边界写成已同意或已发生；
- `mechanical_callback`：为显示“贴合”而反复回扣相同证据；
- `training_topic_overuse`：Alex 在非训练主题连续把话题拉回训练/目标；
- `generic_voice`：回复可替换为任意 NPC 的通用鼓励或书面总结；
- `repeated_opener`：同一多轮案例重复使用相同开场。

自动评分只作筛选信号，不替代人工判断。每个结果保留 `caseId`、实际 Provider、延迟、用量、轮次、阶段、渠道、调情强度和安全标签；网页显示完整多轮对话、预置上下文和原始对白参照，但不返回 `prompt`、API key、Token 或未脱敏请求体。

### 5. 测试策略

先写失败测试，再实现：

1. `test_character_quality_eval.py`：新增元数据归一化、成人/自愿前置条件、不可恋爱角色禁止调情、至少三轮高好感案例和阶段矩阵测试。
2. `test_profile_index.py` / `test_profile_context.py`：验证 Alex 同义主题命中、角色/阶段/渠道排序和冲突证据降权。
3. `test_prompts.py`：验证调情强度、关系边界、渠道、待确认邀约、多轮历史和“不机械回扣”约束进入正确 Prompt 区域。
4. `test_behavior_quality.py`：验证新增专项标签的纯函数判定和结果脱敏。
5. `test_quality_pipeline.py` / `test_quality_results.py` / `test_external_dialogue_lab.py`：验证多轮结果持久化、浏览器筛选与强度/阶段显示，不暴露敏感字段。
6. 生产改动后运行定向 Bridge 测试、完整 Bridge 测试、Python 语法检查和 `git diff --check`；随后用当前 5678 Bridge 和百炼 Qwen 生成新的独立评测工件，统计真实用量。
7. 浏览器核验至少检查每个主要角色的高好感案例、三档调情强度、线上/当面差异和 Alex 非训练主题案例；质量结论以人工浏览与自动标签共同报告，不能只用通过数代替。

## 数据流与错误处理

案例定义 → 元数据校验 → ContextBuilder 选择阶段/渠道/主题证据 → PromptBuilder 注入边界与历史 → Provider 生成 → 格式与质量标签 → 脱敏结果工件 → `/api/quality/results` → `/test` 三视图浏览。元数据不合法的案例在生成前失败并给出字段级错误；模型输出为空、渠道越界或持续格式噪声时保留错误/标签，不把错误结果写入角色资料库。生成过程遇到 Provider 失败只记录脱敏错误和已消耗用量，不能用 fallback 回复冒充云端质量结果。

## 验收标准

- 主要角色均有可在 `/test` 中筛选到的高好感多轮案例；案例详情明确显示阶段、心数、渠道、剧情进度和调情强度。
- 轻度、中度和成人向直白案例穿插出现；陌生/未确认关系和不可恋爱 NPC 不出现越界调情要求。
- 线上与当面案例的动作和邀约边界可在自动测试及人工浏览中区分。
- Alex 至少有一组非训练主题的高置信度成对语气示例，职业球员/职业选手同义话题可命中同一行为证据，且专项标签能识别训练话题过度与通用模板。
- 定向测试和完整 Bridge 测试均通过；新批次有独立工件、真实 Provider/用量记录和浏览器可查看结果。
- 不修改用户密钥、Cookie、个人数据、正式存档或游戏部署目录；未完成的游戏内验证继续明确标注为未完成。
