# 高好感案例与角色表达变化设计

## 背景

当前 `/api/quality/cases` 已返回 23 个固定案例，其中有 7 个 `close` 案例和 1 个 `married` 案例，但测试例浏览器没有关系阶段筛选，列表中的阶段与好感度也不突出。用户实际浏览时很难发现高好感案例。

当前 Prompt 已经提供原版对白、角色语气卡和历史反重复规则，但把“口语化”主要表达为正向提示。模型仍可能在多轮中重复“嗯、哦、啊”等开场或语气词，导致中文僵硬。问题应通过结构化的表达变化提示和可见的质量标记解决，不使用事后字符串替换。

## 目标

1. 让高好感案例成为测试例浏览器中的一等筛选项，并在列表和详情中清晰展示阶段、好感度、渠道和预置历史。
2. 在不改变原文资料和角色事实的前提下，降低同一语气词、同一开场和机械口语模板的连续重复。
3. 让测试页面能提示“重复语气词”与“重复开场”等质量风险，但不把自动提示冒充人工角色判断。
4. 保持 Wizard/Rasmodia canonical ID、云端默认路由、网页会话持久化、游戏端逻辑和已有评测工件不变。

## 非目标

- 本轮不重新生成云端评测，不修改或覆盖已有结果。
- 本轮不重写原版对白资料、不新增未经来源确认的角色事实。
- 本轮不做模型微调，不替换 Qwen API 或本地 Qwen fallback。
- 本轮不对生成文本做简单的正则删词或强制替换。

## 设计

### 1. 测试例浏览器

在现有“按类型筛选”旁增加“关系阶段”筛选，至少包含“全部阶段”“初识”“熟悉”“朋友”“高好感”“亲近”“婚后”。“高好感”映射到 `close`、`dating`、`married`、`parent`，当前案例数显示在按钮上。筛选为空时显示清晰的空状态，而不是隐藏列表。

每个案例列表项直接展示：角色名、关系阶段、好感度心数、聊天渠道、是否有预置历史、生成结果状态。详情页继续展示完整场景条件和剧情进度，并将高好感标签使用稳定的视觉强调。覆盖面板增加高好感案例总数，方便确认本轮是否真的测到了该阶段。

筛选只改变浏览状态，不修改案例定义和 API 返回结构；默认仍显示全部，避免破坏已有链接和选择逻辑。

### 2. 角色表达变化

在现有 `PromptBuilder` 的 voice card 之后增加一个小型表达变化卡，数据只来自当前角色的 `speechParticleHints`、近期 assistant 历史和当前阶段：

- 语气词是可选项，不是每轮必填项；没有自然需要时直接从正文开始。
- 同一回复最多使用一个短口语颗粒；同组三轮不重复已经使用的颗粒。
- 最近使用过的开场前缀和完整开场不能再次使用；可直接用事实、称呼或正文起句。
- 变化的是停顿、句长、开场和收尾，不能为了变化改变角色事实、强行引入主题或把短答扩成长篇。
- 关系阶段优先级高于通用口语提示：高好感可以更自然、更直接，但仍保留角色原有的节奏和边界。

添加纯函数质量检查，读取单条回复和已生成轮次，返回脱敏的 tags/counts，例如 `repeated_speech_particle`、`repeated_opening`、`too_many_speech_particles`。它只用于评测结果和页面提示，不改变回复内容。旧结果没有这些字段时页面按“未检测”处理。

### 3. 测试与验证

- 页面契约测试验证阶段筛选、计数、好感度展示、高好感覆盖指标和质量提示标记。
- Prompt 测试验证表达变化卡的位置、同组轮次限制、历史颗粒过滤和不改变事实的要求。
- 质量检查单元测试覆盖单颗粒、多颗粒、连续重复、不同颗粒和空回复。
- 运行定向测试、完整 Bridge 测试、JavaScript 语法检查和 `git diff --check`。
- 本轮不消耗云端额度；待结构和测试稳定后，再单独决定是否发起小批量云端复测。
