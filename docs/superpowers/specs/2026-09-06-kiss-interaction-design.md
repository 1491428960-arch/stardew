# AI 聊天后的原版亲吻交互设计

## 目标

让一次确实完成有价值关系修复的 AI 聊天可以自然衔接原版亲吻动作，同时保留现有右键交互习惯：

```text
有价值的关系修复完成并结束聊天
    → 第一次右键同一个 NPC：播放一次亲吻
    → 亲吻动画结束
    → 第二次右键同一个 NPC：打开继续聊天
```

本阶段只实现亲吻，不增加拥抱按钮、不监听键盘快捷键，也不让 NPC 改变日程、路线、坐标或原版 `spouse` / `datingFarmer` 状态。

## 交互边界

- 只有当前 `ChatInputMenu` 中的一轮玩家输入和 NPC 回复确实完成了关系修复，关闭菜单时才会挂起亲吻；非 fallback、非空只是必要条件，不是充分条件。
- 关系修复必须对应当前 NPC 的活动嫉妒/调解问题，或本轮明确出现关系冲突，并且 NPC 回复包含承认并解释、修复/履约或明确给空间等证据。普通闲聊、普通回顾、单纯安慰、亲密表达和仅有有效回复都不能触发。
- 同一个聊天菜单中的多轮回复最多产生一个待亲吻状态；只要其中一轮完成了有价值修复即可挂起一次。无回复、空输入、请求异常、fallback、topic 空输入和讨论未来排期/时间分配都不产生待亲吻。
- 待亲吻只绑定当前 NPC、当前游戏日和当前地点。跨天、换地点、回到标题或重置服务时清除。
- 第一次右键必须先检查待亲吻；同一 NPC 的待亲吻在事件、节日、距离过远、菜单打开、玩家使用工具、骑马、坐下、不可移动或已有动作时保留并抑制本次右键，不直接打开继续聊天。
- 亲吻只对恋爱、婚后、育儿阶段，或故事状态中明确存在 `dating` / `engaged` / `married` 关系的当前 NPC 生效；初识、熟悉、朋友和仅有亲近阶段不生效。
- `Farmer.PerformKiss` 负责玩家原版亲吻动画；NPC 如果有 `CharacterData.KissSpriteIndex`，则临时播放对应帧并在动画结束后恢复原方向和普通动画。
- 动画期间抑制右键。动画完成后保留继续聊天目标；下一次右键沿用现有 `TryOpenRepeatChat` 打开聊天。
- 原版 `DialogueBox` 的观察和没有完成关系修复时的继续聊天行为不改变。

## 组件与数据流

1. `ChatInputMenu` 保存每轮玩家输入与 NPC 回复，并在本菜单内累计是否完成过有价值关系修复，通过关闭回调传出该结果。
2. `FaceToFaceConversationCoordinator` 保存 `AwaitingKiss` / `Kissing` 状态，负责一次性消费、目标校验和与继续聊天的顺序。
3. `RelationshipRepairRules` 和 `KissInteractionRules` 保存可测试的关系修复语义、关系阶段、右键前置条件和动画完成规则；生产代码不把游戏对象塞进纯规则函数。
4. `NpcKissAnimationController` 负责调用原版玩家动作、播放 NPC kiss frame、轮询结束并恢复 NPC。
5. `ModEntry` 把待亲吻处理放在现有重复聊天处理之前，并注册 `UpdateTicked`；不添加键盘入口。

## 失败与恢复

- 原版动作前置条件不满足时不清除待亲吻，抑制本次同 NPC 右键，等待玩家下次在可执行状态重试。
- NPC 缺少 kiss frame 时仍可播放玩家原版亲吻，动画控制器只跳过 NPC 帧。
- 动画最多等待 2 秒；若玩家动作没有恢复可移动状态，也会恢复 NPC 并结束锁定，避免卡死。
- 关系修复判定采用失败关闭：无法确认关系问题或修复证据时，只走普通续聊，不影响对白显示、记忆记录和 NPC 的正常聊天。
- 菜单、地点、日期或服务生命周期变化时清除短期交互状态；不写入存档，避免把一次性动作变成长期事实。

## 验证范围

- C# 规则测试覆盖：普通有效回复不能挂起、活动嫉妒/调解被明确修复才可挂起、普通安慰/亲密表达/排期不能挂起、fallback 不能挂起、关系阶段限制、同目标右键优先级、一次性消费、动画未结束不能续聊、动画完成后允许续聊。
- SMAPI 构建和全量单元测试使用 `EnableModDeploy=false`、`EnableModZip=false`，不启动游戏、不部署 DLL。
- 本阶段不做游戏内视觉验证；原版动作资源的最终姿态需要后续获得明确实机验证授权后再测。
