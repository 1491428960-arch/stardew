# 角色专属情绪纹理设计

日期：2026-09-14

## 目标

解决角色对白“情绪过稳”的问题：保留每个 NPC 的核心性格、关系和同意边界，允许被当前话题触发时出现短暂的嘴硬、迟疑、改口、害羞、认真或退缩，让回复不再每轮都快速整理成完整、平滑的标准答案。

## 范围

- 为 deep-flirt 覆盖的 8 个角色提供各自的 `emotionTexture`。
- Prompt 只透传当前角色的纹理，允许模型从当前刺激中表现一个局部反应。
- 保留现有 `emotionRange`、`currentMood`、关系阶段和 Guard 边界；不引入全局随机情绪。
- 不让 Guard 因为情绪波动不足而重试，不做字符串后处理，不改变采样参数和历史结果。

## Prompt 数据流

`voiceStyle.emotionTexture` 是可选角色资料字段。压缩后的 `voice_card` 保留它，`naturalMode` 下增加一条短指令：纹理只是表达可能性，按当前刺激最多表现一个微反应；可以通过停顿、改口、短暂回避、玩笑后认真或突然变短来体现；不要直接说出情绪标签，不要为了展示纹理而凭空制造冲突。

没有 `emotionTexture` 的角色保持现有 Prompt。默认套件不改变 `mustMention`、conversation lead、关系和 Guard 契约。

## 测试与验证

- 先增加失败回归：8 个角色的 Prompt 各自带独特纹理；自然模式契约包含“微反应/改口/停顿”而不要求说出标签；无纹理的默认角色保持旧行为。
- 最小实现后运行自然模式定向测试，再运行 Bridge 全量回归、`compileall` 和 `git diff --check`。
- 不发起 DeepSeek/Gemini 请求；真实自然度留到后续小批量 A/B 验证。
