# 原生风格 AI 聊天界面设计

## 1. 背景与结论

当前 `DialogueMenu` 只是链路验证原型：窗口尺寸固定、点击任意正文区域都会发送固定的「你好」，回复直接用 `DrawString` 绘制，无法输入、换行或连续聊天。游戏内截图已经证明 Bridge 链路可用，但界面仍然像调试菜单。

本阶段将其改造成原生风格聊天界面：复用 Stardew Valley 的 `DialogueBox`、字体、头像、鼠标光标和按钮贴图；面对面入口先执行原版寒暄，再进入 AI 聊天；F8 入口复用同一套聊天服务和界面。不接入 Smartphone，不引入新的美术资源，也不替换 NPC 原版日常对白。

## 2. 目标与非目标

### 2.1 目标

1. 聊天面板在不同分辨率下自适应，视觉比例接近原版菜单，不再使用 600 × 360 的调试窗口。
2. 玩家可以输入中文，使用 Enter 发送，并通过鼠标完成发送、找话题、背包和结束操作。
3. NPC 回复自动换行和分页，等待、成功、离线状态以界面状态呈现，不把技术状态写进 NPC 台词。
4. 面对面交互先显示原版寒暄，再由玩家选择「继续聊聊」或「先告辞」。
5. 「让对方找话题」复用同一上下文链路，生成符合人设、关系阶段和当前场景的主动开场。
6. 「背包」支持选择物品并预览展示、分享或赠送；预览不消耗物品，正式赠送沿用原版礼物处理。
7. Bridge 离线、超时、返回无效数据或玩家退出菜单时，游戏仍可继续运行，异步回复不会覆盖其他菜单。

### 2.2 非目标

- 不接入 Smartphone 或其他手机框架。
- 不制作全屏视觉小说界面，不新增独立美术资源包。
- 不拦截或改写所有原版 NPC 台词、日程、事件和过场对白。
- 不让 AI 直接修改好感度、婚姻、物品数量或剧情状态；这些仍由本地规则和原版逻辑决定。
- 本阶段继续以现有 Rasmodia/Wizard 双 ID 解析作为测试范围，不扩展完整 NPC 选择器。

## 3. 交互流程

### 3.1 面对面入口

1. 玩家面向 NPC，按原版交互键。
2. 协调器记录候选 NPC，但不替换原版交互；每日台词、剧情台词和 Mod 台词照常打开原生 `DialogueBox`。
3. 原版对话全部关闭后，若场景允许续聊，则显示原生风格选择框：「继续聊聊」和「先告辞」。
4. 选择「继续聊聊」进入 `ChatInputMenu`；选择「先告辞」回到游戏世界。
5. 玩家发送消息后，界面进入等待状态。Bridge 成功返回时，NPC 回复以原生风格消息区显示；关闭回复后返回输入状态，可继续多轮聊天。
6. 玩家按 Esc、点击「结束聊天」、离开有效场景、开始事件或进入存档流程时，回到空闲状态并取消未完成请求。

### 3.2 F8 入口

F8 保留为开发和备用入口。当前仍解析 Rasmodia/Wizard，打开后直接进入 `ChatInputMenu`，不再创建独立的固定问候菜单。后续扩展其他 NPC 时，只替换目标解析器，不改变聊天 UI 和服务层。

## 4. 界面布局

### 4.1 自适应尺寸

聊天窗口使用视口尺寸计算位置和大小，左右保留安全边距，宽度约为视口的 65%～70%，高度约为视口的 55%。设置最小尺寸，避免小窗口下按钮和输入框重叠；不再依赖固定的 600 × 360 坐标。

界面打开时绘制轻微的半透明暗色遮罩，降低地图背景干扰。所有可点击区域都使用原版纹理框和鼠标光标，保留游戏的像素风格。

### 4.2 三层结构

```text
┌────────────────────────────────────────────┐
│ [NPC 头像] Rasmodia · 亲近                 │
├────────────────────────────────────────────┤
│ NPC：最近的一条回复……                     │
│                         玩家：刚才的消息…… │
│ NPC：正在生成的下一条回复……               │
├────────────────────────────────────────────┤
│ [输入框……] [发送] [找话题] [背包] [结束]   │
└────────────────────────────────────────────┘
```

- **标题区：** 显示 NPC 头像、显示名和关系阶段；不显示 `provider`、`fallback` 等技术字段。
- **消息区：** 只保留当前会话最近若干条消息，使用统一换行函数；消息过多时移除最旧的显示记录，但不删除持久化记忆。
- **操作区：** 输入框、发送、让对方找话题、背包和结束按钮固定在底部，等待请求时禁用重复提交。

### 4.3 状态文案

- 空闲：输入框显示提示文字「想和她聊些什么？」。
- 等待：操作区显示「正在思考……」，允许结束聊天，不允许再次发送。
- 成功：只显示 NPC 自然回复。
- 离线或超时：显示「暂时联系不上她。」并提供「重试」和「结束」；详细异常只写入 SMAPI 日志。
- 空消息、超长消息或失效物品：在输入区附近显示简短校验提示，不创建记忆记录。

## 5. 输入、主动话题与物品

### 5.1 文本输入

输入组件使用 SMAPI 的键盘分发机制（`Game1.keyboardDispatcher`）接入原生风格文本框，支持中文输入、退格、光标移动和 Enter 发送。输入内容沿用 Bridge 现有长度限制。若运行环境无法接收中文 IME，界面仍保留推荐话题和「让对方找话题」按钮，确保聊天入口可用，并在日志中记录输入兼容性问题。

### 5.2 NPC 主动找话题

「让对方找话题」发送显式的主动开场请求，消息类型与普通玩家消息区分。Bridge 只负责生成候选话题，不改变关系数值。上下文包括 NPC 人设、当前时间、地点、天气、原版心级、关系阶段、最近记忆和已完成事件；本地仍负责记忆写入和关系规则裁决。

### 5.3 背包物品

点击「背包」后打开原版风格物品选择器，只列出玩家当前背包物品。选中物品后显示「展示」「分享」「赠送」「取消」四个动作：

- 展示和分享只把物品信息发送给 Bridge，不扣除物品。
- 赠送在确认后调用原版礼物流程，物品消耗、每日送礼限制和好感度变化由原版逻辑处理。
- Bridge 接收物品名称、类别、品质和 NPC 偏好结果；AI 只生成符合该偏好的自然反应。
- 任何动作失败或玩家取消，都不写入聊天记忆，不改变存档。

## 6. 代码职责与状态机

### 6.1 组件边界

保留 `BridgeClient`、`GameStateCollector`、`StoryStateStore`、关系阶段规则和记忆规则。新增或替换以下职责：

- `ConversationService`：统一组装上下文、发送普通消息或主动话题请求、管理当前会话历史和取消令牌。
- `FaceToFaceConversationCoordinator`：监听原版 NPC 对话生命周期，只负责续聊选择和状态切换。
- `ChatInputMenu`：绘制聊天窗口、处理文本输入、按钮点击、等待和错误状态。
- `InventoryItemPicker`：展示背包物品，输出不可变的物品选择结果，不直接改存档。
- `DialogueMenu`：迁移期间保留最小兼容入口；新流程稳定后移除固定问候和直接 `DrawString` 绘制。

### 6.2 生命周期

```text
Idle
  → AwaitingVanillaDialogue
  → AwaitingContinuationChoice
  → Composing
  → Sending
  → ShowingReply
  → Composing
```

任意状态遇到存档、返回标题、事件、菜单被替换、NPC 失效或玩家退出时，都取消请求并回到 `Idle`。只有 Bridge 正常返回且消息非空时才写入 `StoryStateStore`；fallback、离线错误、主动取消和空消息不写入。

## 7. 测试与验收

### 7.1 自动化测试

- 自适应窗口计算在常见视口和最小视口下不越界。
- 输入框空消息、超长消息和 Enter 发送规则正确。
- 等待状态阻止重复发送，取消后异步回复不会改变当前菜单。
- 主动话题请求与普通消息使用正确的请求标记。
- 物品预览不修改背包；取消和失败不写记忆。
- 面对面状态机只出现一次续聊选择，存档退出后能回到 `Idle`。
- Bridge 离线、超时和无效响应都能安全结束等待状态。

### 7.2 游戏内验收

1. 面对 NPC 交互时先看到原版寒暄，再看到续聊选择。
2. 进入聊天后窗口比例、头像、文字换行和按钮都不越界。
3. 可以输入中文、连续发送 3～4 轮消息，并看到 NPC 回复。
4. 点击「让对方找话题」后出现符合当前 NPC 的主动开场。
5. 选择背包物品后可以展示或分享；未确认赠送前物品数量不变。
6. 关闭 Bridge 后可以重试或退出，游戏不崩溃、不锁死。
7. 保存、读档、返回标题后故事状态和聊天菜单均正常清理。

## 8. 实施顺序

1. 先提取 `ConversationService`，用现有 F8 入口保护 Bridge、记忆和关系状态回归。
2. 实现 `ChatInputMenu`，先完成原生风格布局、输入、连续对话和错误状态。
3. 将 F8 入口切换到新菜单，删除固定「你好」和调试状态绘制。
4. 实现面对面原版寒暄后的续聊状态机。
5. 接入主动话题和 `InventoryItemPicker`，先完成展示、分享，再接原版赠送确认。
6. 更新测试用例、README 和交接文档，最后进行 Fake Provider 与真实游戏冒烟测试。
