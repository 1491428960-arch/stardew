# 恋爱阶段主动亲密表达设计

## 背景

最新云端批次的 #24 `wizard-dating-invite` 暴露出一个明确的行为缺口：Rasmodia 能识别玩家说“想你了”，却只表达意外，没有回接想念、亲密玩笑或下一步安排。当前 Prompt 的 `light` 规则明确要求“允许接住玩家主动的轻微暧昧，但不要主动升级”，因此模型拿到的是“不要越界”的否定约束，而不是“在关系成立时如何自然主动”的正向行为示范。

当前 `dating` / `married` 的已审核行为示例也很少，现有示例主要覆盖 `friend` / `close`；角色资料中的“可以提出邀约”是可选策略，不能稳定驱动角色在玩家不会说情话时主动推进。

## 目标

1. 在恋爱和婚后阶段，玩家只说日常话或笨拙地表达时，角色能在回答当前内容后主动给出一小步、符合自身性格的亲密回应。
2. 将主动亲密表达拆成关系阶段、调情强度、渠道和角色行为四层约束，避免所有角色变成同一种甜腻腔。
3. 为五个主要角色补充 `dating` / `married` 的已审核行为示例，使 Prompt 有可模仿的实际动作，而不是只看到抽象标签。
4. 保留 Shane 的冷淡、疲惫、拒绝和结束聊天能力；主动不等于强行热情或每轮都调情。
5. 让评测能区分“有主动亲密信号”“过度升级”“仍然像本人”和“仅仅复述玩家”，但不使用字符串后处理改写回复。

## 非目标

- 不把 Wizard 与 Rasmodia 拆成两个实体，继续使用 canonical `npcId=Wizard`。
- 不让初识、普通友情、不可恋爱 NPC 自动出现恋爱或成人内容。
- 不让线上聊天写成已经见面；远程邀约只能是待确认安排，当面互动才允许推进现场动作。
- `explicit` 不改成无条件主动露骨内容；仍需已建立关系、成人同意和当前话题许可。主动性本轮主要覆盖轻度和直接的情感亲密。
- 不把未经人工审核的新生成回复写回角色资料库，不覆盖已有评测工件。
- 不切换当前 Codex 模型、Bridge 默认百炼 Qwen 配置、本地 Qwen fallback 或游戏部署目录。

## 设计

### 1. 主动性行为层级

在现有 `stagePolicy` 和 `qualityContext` 上增加结构化的亲密主动性字段，保持旧请求兼容：

- `initiativeMode`：`none`、`responsive`、`proactive`、`guarded`。
- `initiativeExpectation`：本轮评测要求是无亲密推进、接住玩家、主动推进一小步，还是允许克制拒绝/结束。
- `initiativeKind`：`affection_signal`、`playful_tease`、`specific_plan`、`guarded_care`、`conversation_exit`，只作为行为意图和结果标签，不作为必须逐字输出的台词。

关系阶段默认策略：

| 阶段 | 默认主动性 |
| --- | --- |
| 初识、熟悉、朋友、亲近 | `none` 或当前话题内的普通主动，不主动恋爱升级 |
| 恋爱 | 在话题轻松、没有边界信号且调情强度为 `light/direct` 时可 `proactive`，回答后最多推进一小步 |
| 婚后 | 可更自然地 `proactive`，主动表达偏爱、陪伴或具体安排；仍需尊重同意和线上/当面边界 |
| 育儿及其他友情阶段 | 不启用恋爱主动性，使用原有关系策略 |

`light` 的主动一步可以是回接想念、偏爱式玩笑、给出陪伴选择或具体但可商量的安排；不要求每轮出现“爱”“想你”等固定词。`direct` 可以更明确地回撩、夸回或提出约会安排。`explicit` 仍以回应已提出且获得同意的成人亲密为主，不因阶段标签凭空添加露骨细节。

角色差异由行为卡和 few-shot 共同约束：

- Rasmodia：克制、古雅、带正式称呼的干燥玩笑；主动表达偏爱时短而明确，不写甜腻告白。
- Sophia：温柔、害羞、带一点俏皮；主动从葡萄酒、绘画或共同日常中提出轻松相处的可能。
- Shane：低调、疲惫、略带防备；主动通常落在“陪着、吃饭、鸡舍、休息”等实际关心，状态差时可以拒绝甜话或直接结束。
- Sebastian：少话、别扭、用音乐、摩托车、代码和具体行动表达在意；不写戏剧化表白。
- Alex：自信、直接、会夸回或逗回对方；把亲密落到行动和玩笑，不变成训练教练或励志演讲。

主动性只在当前话题适合时触发：工作故障、明确拒绝、悲伤、隐私边界和玩家要求结束时，优先回答或收口，不为了展示恋爱行为硬插调情。三轮对话中同一种主动动作不能机械重复，允许第二轮改为具体安排、第三轮自然收束。

### 2. Prompt 与资料管线

1. `stage_policy.py` 为 `dating` / `married` 提供可执行的 `affectionInitiative`，并为五个主要角色提供角色化覆盖；原有 `initiative`、`followUp` 和边界策略保持不变。
2. `prompts.py` 在关系阶段、质量边界和历史之后注入短的 `affection_initiative` 卡：先回答当前输入，再根据 `initiativeMode` 选择至多一个亲密动作；不得复述卡名、强度或规则，不得把玩家未确认的邀约写成已发生。
3. 删除/改写会压低主动性的 `light` 文案。新规则必须明确：在 `proactive` 且关系成立时，不需要等待玩家先说情话；但 `explicit` 仍遵循同意边界，Shane 等角色仍可 `guarded` 或退出。
4. `behavior-examples.json` 增加五个角色在 `dating` / `married` 的 `human_approved` 示例，至少覆盖：回接想念、轻微回撩、具体陪伴安排、角色化拒绝或收口。示例必须包含渠道、关系阶段、话题、情绪和行为函数；不得把同一套台词换名复用。
5. 重新生成派生 profile index，并验证 `ProfileIndexStore.behavior_examples()` 在 `dating` / `married` 场景确实返回当前角色和渠道匹配的示例。派生索引仍是生成文件，源行为示例和构建命令才是可审查来源。
6. 只把已发生的对话放进 history；主动动作的类型可由评测结果记录，但不把模型的未确认承诺写回长期事实或角色资料。

### 3. 评测案例与结果

扩展 `CharacterQualityTurn` 的可选元数据，让现有案例保持兼容：

- #24 保留为 Rasmodia 线上恋爱回归，并明确第一轮应接住想念、无需玩家先写完整情话；后续轮次分别检查休息关心和待确认见面安排。
- 为 Sophia、Shane、Sebastian、Alex 各增加至少一个“玩家只说日常/笨拙表达，角色主动给出亲密信号”的三轮案例；同时保留 Shane 的低落拒绝/结束路径。
- 每个主要角色至少覆盖一个 `dating` 和一个 `married` 或等价高亲密案例；`remote` 与 `face_to_face` 成对覆盖，线上案例不能完成现场动作。
- 评测记录 `initiativeExpectation`、`initiativeKind`、`initiativeDetected`、`initiativeTags`，与现有 `score`、`progression`、`styleQuality` 并列。检测只产生诊断信号，不改写回复，也不把单个词命中当作“贴角色”。
- 自动标记至少包括：`missing_proactive_affection`、`generic_romance`、`flirt_stage_mismatch`、`romance_boundary_violation`、`mechanical_callback`、`guarded_exit_allowed`。自动分数仍是筛选信号，最终判断以浏览器中的完整多轮对话和原文参照为准。

### 4. 浏览器展示

在现有案例浏览器中，案例详情增加“主动性期待”与“主动动作类型”两项，列表增加简短标签：`主动回撩`、`具体邀约`、`克制接住`、`允许收口`。完整三轮 transcript 继续是主要查看对象，避免只看标签或通过率。

## 数据流与错误处理

案例定义/角色行为示例 → 元数据校验 → 按角色、阶段、渠道和话题检索 → Prompt 主动性卡与历史约束 → Provider 生成 → 格式/边界/主动性诊断 → 脱敏结果工件 → `/api/quality/results` → 浏览器人工复核。

- `initiativeMode`、阶段、恋爱资格或成人同意冲突时，在生成前报字段级校验错误。
- 找不到阶段匹配的行为示例时不伪造示例；保留安全的基础角色策略并在诊断中标记证据不足。
- 模型没有主动亲密信号时保留原文并标记 `missing_proactive_affection`，不使用固定句子补写。
- 模型越过远程/当面、拒绝、同意或关系阶段边界时保留错误结果和脱敏标签，不写回资料库。
- 旧案例、旧工件和没有主动性字段的请求继续按现有逻辑读取；新批次使用独立目录，不覆盖旧批次。

## 测试策略

按 TDD 执行，先写并运行失败测试，再写实现：

1. `test_stage_policy.py`：验证恋爱/婚后启用主动性、友情阶段关闭、五个角色有不同覆盖、Shane 保留 guarded/exit 能力。
2. `test_profile_index.py`：验证 `dating` / `married` 的行为示例按角色、阶段和渠道返回，缺失时安全为空。
3. `test_prompts.py`：验证主动性卡位置、`proactive` 不要求玩家先说情话、`explicit` 仍受同意约束、远程不写成见面、玩家明确结束时不调情。
4. `test_character_quality_eval.py`：验证 #24 元数据、日常主动案例、婚后/恋爱覆盖和主动性期望的序列化；验证 Shane 的允许收口案例不会被错误判为缺少主动。
5. `test_behavior_quality.py` 或现有质量纯函数测试：验证主动性诊断和边界标签只记录不改写文本，并避免把普通“陪你聊”误判成成人升级。
6. 运行定向测试、Bridge 全量测试、Python 语法检查和 `git diff --check`；重建索引后再用当前 5678 的百炼 Qwen 生成独立小批次，记录实际 Provider、请求数和 Token。
7. 浏览器至少查看 #24、五个角色的恋爱/婚后案例、一个 Shane 收口案例，以及远程/当面各一组；不以自动通过率单独宣称角色质量达标。

## 验收标准

- #24 第一轮不再只说“有些意外”：在不要求玩家先写情话的情况下，能自然接住关系和情绪，并符合 Rasmodia 的克制语气。
- 五个主要角色在恋爱/婚后场景各有可辨识的主动亲密表达；主动动作、句长、话题和收尾方式有角色差异。
- Shane 在低落或边界场景仍可以短答、拒绝或结束，不被“主动调情”规则强行变甜。
- 远程邀约保持待确认，当面互动才推进现场动作；显式成人内容不因标签自动出现。
- 新批次包含编号、完整三轮结果、主动性诊断和真实用量；浏览器能直接查看完整上下文与回复。
- 定向测试和完整 Bridge 测试通过；未修改密钥、Cookie、个人数据、正式存档或游戏部署目录，未完成的游戏内验证继续明确标注。
