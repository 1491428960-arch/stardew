## 3. 当前资料库状态

资料入口位于 `data/personas/`，Bridge 会按来源 Mod 叠加人物资料：

| 文件 | 当前覆盖 | 现状 |
| --- | --- | --- |
| `vanilla.json` | Wizard、Shane、Alex | 只有 3 名原版 NPC，且主要是少量核心性格标签 |
| `sve.json` | Wizard/Magnus、Sophia、Victor、Olivia、Andy、Lance、Claire、Morris | 8 个覆盖项，内容仍较简略 |
| `female-bachelors.json` | Shane、Alex、Elliott、Harvey、Sam、Sebastian | 主要处理称谓与代词，不含完整娘化后人物设定 |
| `rasmodia.json` | Wizard、Rasmodia | 处理显示名、代词、称谓和双 ID 兼容 |

结论：当前资料库足以验证“按 Mod 来源叠加人设”和“显示名／内部 ID 变化”这套技术路径，但还不足以让全体原版及 SVE NPC 在长对话中稳定贴合人设与剧情进度。主要缺口包括：

1. 原版与 SVE NPC 覆盖不全。
2. 人物经历、关系网、语言习惯、价值观、秘密和敏感话题规则过于简略。
3. 心级、事件、季节、节日、主线分支和已完成剧情对应的分阶段知识尚未系统建模。
4. “近期发生的事情”已有数据字段和 Prompt 管道，但游戏侧可收集事件仍有限，尚未完成全流程游戏内验证。
5. 男性角色娘化目前主要解决身份与代词兼容，缺少针对具体内容包文本的细化资料。

下一阶段不应直接无边界堆资料。建议先以 Rasmodia、Sophia、Shane 娘化版作为 3 个代表角色，建立可测试的人设／剧情分层格式，再扩展到全员。
