# 本地与云端模型质量、速度与开销评估

日期：2026-08-28
研究问题：本地 Qwen 是否足够，以及接入其他模型的质量、速度、成本和风险。
研究范围：Bridge 当前本地路由、已完成的 Qwen3.5 4B/9B 实测、阿里云角色扮演模型、DeepSeek V4 Flash，以及少量高质量对照模型。
截止时间：2026-08-28（价格和模型服务会变化，使用前仍应在控制台复核）。

## 结论

### 总判断

建议接入一个云端模型做 A/B 对照，但现在不建议直接替换本地 Qwen，也不建议一次接入很多 Provider。

最实用的顺序是：

1. 保留本地 `qwen3.5:9b` 作为默认和离线兜底。它的输出速度已经够做游戏聊天，当前主要短板是“像不像角色”、中文自然度和证据投影，不是纯生成速度。
2. 第一优先测试阿里云 `qwen-plus-character`。它是明确面向游戏 NPC 和角色扮演的模型，价格低、中文接入路径相对直接，最有可能回答“换模型是否真的改善角色感”这个问题。
3. 把 DeepSeek `deepseek-v4-flash` 作为低价对照或故障备用，而不是默认角色模型。它的官方定位和接口能力很强，但不是专门的角色扮演模型；默认 thinking 还会增加延迟，当前 Bridge 需要显式关闭或适配。
4. Claude Haiku 4.5、Kimi 等可以作为第二轮高质量对照，不应成为当前第一步。它们会增加外网可用性、账号、隐私和成本变量。

### 对“本地 Qwen 质量和速度是否不行”的回答

- **速度：基本够用。** 已有热模型流式实测为：Qwen3.5 9B 首段内容延迟约 420 ms、约 64 tok/s；4B 约 321 ms、约 97 tok/s。9B 冷启动约 7.1 秒，属于首次加载成本，不是每轮正常体验。刚刚对当前 `5678` Bridge 的一次新请求返回 `provider=local`、`fallback=false`，总耗时约 22.0 秒，原因更接近模型刚重新加载；随后 `/api/ps` 显示 9B 已驻留显存。
- **质量：仍然不够稳定，但不能只归咎模型。** 同一套固定 Rasmodia 7 场景中，9B 通过 7/7，4B 通过 6/7；但原文抽样能看到“星界、魔法、变量”等词在普通问候里过度出现，以及较书面、较长的回答。这说明模型能力不是唯一瓶颈，当前资料选择、关系阶段、远程/面对面场景投影和 Prompt 约束仍有影响。
- **更大本地模型不适合当前机器。** 官方 Ollama 标签显示 Qwen3.5 27B Q4 约 17 GB；本机是 RTX 3070 Laptop 8 GB 显存、约 15.8 GiB 可用物理内存。9B 当前实际驻留约 5.49 GB、运行上下文为 4096；直接上 27B 会带来内存/显存溢出或明显变慢的风险，不能把它当作低成本升级路线。

因此，换云端模型的目的应是验证角色质量上限，而不是为了解决一个已经基本可接受的首字延迟问题。

## 判断依据

### 1. 本机和项目事实

当前工作树有大量未提交的既有开发修改，本轮没有覆盖或回滚它们，也没有修改 Bridge 默认配置。当前代码已经具备一个可扩展但较简单的路由骨架：

- `bridge/src/stardew_ai_bridge/config.py` 提供 `local`、`cloud`、`cloud_enabled` 和环境变量配置；云端默认关闭。
- `bridge/src/stardew_ai_bridge/providers.py` 提供 `ProviderRouter`，顺序是 local → cloud → fallback；`OpenAICompatibleProvider` 可以发送 `model`、`messages` 和 Bearer API key；`OllamaNativeProvider` 额外发送 `stream:false`、`think:false` 和 `num_predict=160`。
- 当前两个 Bridge 地址 `http://127.0.0.1:5678/health` 和 `http://127.0.0.1:5679/health` 均实际返回 HTTP 200、`{"status":"ok","provider":"local"}`。
- 当前隔离 Ollama 的 `/api/tags` 实际列出 `qwen3.5:4b`（约 3.4 GB）和 `qwen3.5:9b`（约 6.6 GB，Q4_K_M）；`/api/ps` 在新请求后显示 9B 实际驻留约 5.49 GB，运行上下文为 4096。
- 本机实测硬件为 NVIDIA GeForce RTX 3070 Laptop GPU、8 GB 显存、Compute Capability 8.6；约 15.8 GiB 可用物理内存。当前盘符剩余空间约为 C 盘 1.73 GiB、D 盘 104.07 GiB、E 盘 206.88 GiB，模型不应再放入 C 盘。

本项目的中文联合索引最近构建结果为 95 profiles、7108 styleSamples、7108 speechEvidence、4 knowledgeFacts、65 warnings。这个数量代表资料被索引，不代表每条资料都适合在每次对话中注入；角色质量仍须按实际回复人工复核。

### 2. 已有本地 Qwen 实测

固定评测包含初识、SVE 事实、朋友阶段、亲近阶段、婚后/Roommate、同日续聊和未触发事件边界，共 7 个场景。工件位于：

- `E:\workspace\projects\stardew-ai-npc.worktrees\story-memory\artifacts\model-benchmark-qwen3.5-9b.json`
- `E:\workspace\projects\stardew-ai-npc.worktrees\story-memory\artifacts\model-stream-metrics-qwen3.5-4b.json`
- `E:\workspace\projects\stardew-ai-npc.worktrees\story-memory\artifacts\model-stream-metrics-qwen3.5-9b.json`

| 本地模型 | 固定场景通过 | 平均非流式耗时 | 热模型首段内容延迟 | 热模型生成速度 | 主要差异 |
|---|---:|---:|---:|---:|---|
| `qwen3.5:4b` | 6/7（另一轮流式工件为 7/7） | 约 2.56 秒 | 约 321 ms | 约 96.6 tok/s | 更快、更省显存；同日续聊中曾只用“它”承接，未明确复述咖啡细节 |

### 4. 角色专用模型为什么值得先测

阿里云角色扮演文档不仅列出专用模型，还给出了与当前项目直接相关的机制：

- `qwen-plus-character` 的定位包括游戏 NPC；官方说明其优化了限定人设指令遵循、话题推进、倾听共情和个性化角色还原。
- 官方建议将角色详细信息、经历/关注点、场景背景、关系和语言长短写入角色设定，并用 assistant 开场白引导后续对话。这与当前项目已经做的 `profile index`、`voiceStyle`、关系阶段和会话历史方向一致。
- 官方支持 `x-dashscope-aca-session` 会话标识和 Session Cache；`qwen-plus-character` 还提供长期记忆选项，允许只发送增量消息，由服务端管理摘要。但这会把一部分会话状态放到云端，必须在实现前明确会话隔离、清理和隐私边界。

这只能证明“它更值得测试”，不能证明它在 Rasmodia、Sophia、Shane 等具体角色上一定胜过本地 Qwen。最终仍要用同一份项目上下文和人工盲评验证。

### 5. 成本估算

统一假设：每轮输入 1,500 Token、输出 200 Token，每月 30 天；不计免费额度、缓存命中、重试、网络费用和税费。每天 20/50/100 轮分别对应每月输入 0.9M/2.25M/4.5M Token，输出 0.12M/0.3M/0.6M Token。

| 模型 | 20 轮/日 | 50 轮/日 | 100 轮/日 |
|---|---:|---:|---:|
| 本地 Qwen | ¥0 API 费 | ¥0 API 费 | ¥0 API 费 |
| `qwen-plus-character` | 约 ¥0.96 | 约 ¥2.40 | 约 ¥4.80 |
| `qwen-flash-character` | 约 ¥0.41 | 约 ¥1.01 | 约 ¥2.03 |
| `deepseek-v4-flash` 非高峰 | 约 $0.28 | 约 $0.69 | 约 $1.39 |
| `deepseek-v4-flash` 高峰 | 约 $0.55 | 约 $1.39 | 约 $2.77 |
| Claude Haiku 4.5 | 约 $1.50 | 约 $3.75 | 约 $7.50 |

当前 Bridge 的完整提示曾接近 2,700 Token。若每轮都按 2,700 输入 Token、仍输出 200 Token，输入部分大约是上述成本的 1.8 倍；以每天 50 轮为例，粗略变为：`qwen-plus-character` ¥3.84、`qwen-flash-character` ¥1.46、DeepSeek V4 Flash 非高峰约 $1.09、Claude Haiku 4.5 约 $5.55。实际账单要以服务返回的 usage 为准，尤其是 reasoning、长期记忆摘要和重试会额外增加用量。

阿里云角色模型官方页面还列出北京地域开通后的免费额度信息，但免费资格和剩余额度属于账号状态，本轮没有登录控制台验证，所以没有从估算中扣除。

## 接入方案建议

### 第一阶段：只接一个云端质量对照

目标不是马上切换默认模型，而是回答“角色专用云模型是否显著改善”。推荐 `qwen-plus-character`，通过现有 `ProviderRouter` 作为显式或可选的 cloud Provider。

当前代码可以复用 OpenAI-compatible 发送骨架，但要补一个专用适配层或可配置扩展：

1. 只从环境变量读取 `BRIDGE_CLOUD_API_KEY`，不写入代码、配置文件、会话记录、测试 fixture 或报告。
2. 保留现有 `local → cloud → fallback`；默认仍 `BRIDGE_CLOUD_ENABLED=false`，测试时才在单独终端启用。
3. 第一轮先沿用项目自己生成的完整 system/profile 和有限历史，不立即启用云端长期记忆，避免同时改变“模型”和“记忆系统”两个变量。
4. 若要使用阿里云的专用 `character_options.profile`、`x-dashscope-aca-session` 和增量消息，必须先写脱敏、会话隔离和失败回退测试，再决定是否让云端保存会话状态。云端长期记忆不是当前游戏存档持久化的替代品。

### 第二阶段：低价控制组

接入 `deepseek-v4-flash` 只用于对照或 fallback。当前 `OpenAICompatibleProvider` 没有通用 `extra_body` 参数，不能直接表达 DeepSeek 文档要求的 thinking 开关；后续应添加 Provider 级参数，而不是把 DeepSeek 特殊字段硬编码到所有模型请求中。实时聊天默认应走 non-thinking，并把最大输出限制在游戏短对白范围。

### 推荐的 A/B 测试设计

每个模型使用完全相同的：

- 角色、显示名、来源 Mod 和关系阶段；
- `vanilla-sve-rasmodia-profile-index-zh-CN.json` 固定版本及其 SHA-256；
- 时间、地点、天气、好感度、已完成事件和最近事实；
- 同一组用户输入、同一段多轮历史；
- 相同的最大回复长度和超时；
- 新建、独立的测试会话，不混用旧网页记录。

建议首轮使用 5 个代表角色 × 8 个场景 × 3 次重复，即每个模型 120 条回复。场景至少包括：普通寒暄、角色核心话题、同日追问、远程邀约后面对面承接、关系阶段边界、未触发事件、拒绝不合理恋爱假设和连续 6 轮不重复。这个规模足以发现稳定问题，又不会产生不可控的测试费用。

评分分为两层：

1. 自动层：空回复、fallback、越界事件、错误身份、历史事实命中、回复长度、重复率、首段延迟、总耗时和实际 usage。
2. 人工层：角色声音、星露谷日常感、中文自然度、情绪/关系阶段、上下文承接、邀约可推进性，每项 1～5 分，并优先采用盲评的成对比较。

只有云模型在“角色声音”和“自然度”上稳定提高，同时不增加事件越界和上下文断裂，才值得把它用于高质量模式；单纯通用知识分数高、回复更长，不算胜出。

## 建议

当前推荐采用“本地默认 + 云端可选增强”的路线：

1. **默认**：本地 `qwen3.5:9b`，保持离线可用和低长期成本；继续压缩普通日常的魔法词、书面化句式和重复开场。
2. **云端首测**：阿里云北京 `qwen-plus-character`，只为同一题集做质量对照；若测试明显提升，再考虑把远程聊天或用户主动选择的“高质量模式”路由到它。
3. **备用/低价对照**：DeepSeek V4 Flash，关闭 thinking 后测速度和自然度，不把便宜误认为贴角色。
4. **暂不做**：不下载 Qwen3.5 27B，不默认开启云端长期记忆，不同时接入 OpenAI、Claude、Kimi、DeepSeek 四个 Provider，也不把 Codex 的 Luna 名称直接当成 Bridge 的 API 配置。
5. **路由边界**：面对面聊天优先保证低延迟和不泄露存档上下文；远程聊天可以作为云端质量模式的首个试点，但云端请求只发送当前 NPC 必要的脱敏状态，不发送完整存档、用户本地路径、API key 或未必要的全量语料。

## 限制

- 本轮没有使用任何云端 API key，也没有向云端发送项目角色资料；阿里云、DeepSeek、Claude、Kimi 的质量和真实延迟尚未在本机同题集实测，因此报告中的适配排序是基于官方定位、接口条件和工程推断，不是最终质量排名。
- OpenRouter 的应用 token 量是平台公开的流量代理，会受接入应用分布、时间窗口和平台统计方式影响；它不能直接解释回复质量，也不能等同于社区投票。RPBench-Auto 的排名信息本轮只看到模型页自述，尚未取得独立复现实验。
- 本轮能验证这些角色模型在公开目录中存在并被使用，但没有找到足够可靠的中文角色扮演盲测，尤其没有“中文 Stardew NPC”专项评测；因此不能把 Euryale、Aion 或 Cydonia 的英文 RP 优势直接外推到本项目。
- 官方价格可能按地域、活动、峰谷、缓存命中、免费额度和账号状态变化；成本表只是估算，不是账单承诺。
- 本地 4B/9B 结果采用固定规则评分和少量人工观察，不能替代 5 个角色的盲评；模型随机性、Prompt 版本和索引版本都会影响结果。
- 当前本机 `/api/ps` 的运行上下文是 4096，不能用 Ollama 标签的 256K 标称值推断项目已经在使用 256K；上下文长度、历史窗口和检索数量仍是后续性能调优变量。
- 报告没有判断云端服务在当前网络、账号实名/付款、地区合规或数据保留策略下是否一定可用；正式接入前必须做一次最小化、脱敏的连通性和失败回退测试。
