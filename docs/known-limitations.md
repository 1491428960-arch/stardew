## 一、打趣（teasing）在正常新档里实际是死代码

这不是 bug，是设计的结果，但你**必须知道**，否则玩到第二年发现它没出现会误判成故障。

**前置条件**（`GroupInvitationTemplates.CanTease`）：
需要当前场次里同时有 **≥ 2 位「已接受」的配偶**（`InOnIt(...).Length >= 2`）。

**一次性规则**（`GroupInvitationTemplates.OneShotThemeIds`，含 `teasing`）：
主题一旦在**自然生成的历史**里出现过一次，**永不再出现** —— 是「用尽」而非「冷却」。
只有自然生成的卡片计入；`Source = dev` 的开发卡**不算数**，不会消耗那一次机会。

**叠加的其它约束**：`GenerationIntervalDays = 2`（两次生成至少隔 2 天）、
`MaxVisibleInvitations = 4`、`ExpirationDays = 7`。

**结论**：正常游玩要等到「同时有多位配偶」才满足前置，**而且只会出现一次**。
**唯一能主动看到它的途径是 `Ctrl+Shift+F9`**（开发入口，产出 `Source = dev` 的卡片）。

## 三、Bridge 单轮回退路径缺两项能力

`bridge/src/stardew_ai_bridge/group_conversation.py` 的 `build_group_prompt`：

- 缺 **fence 容忍**（模型输出被 ``` 包裹时的剥离能力）
- 缺 **`topic` 参数**（拿不到 `invitation.topic`，模型在回退时失去锚点）

**生产路径走的是 `build_group_messages`（多轮）**，所以日常游玩**不受影响**。
只在多轮路径失败、回退到单轮时退化。

**未修的理由**：这是冗余路径，修它要同步维护两套 prompt 模板，且回退本身是罕见分支；
收益小于「两套模板不一致」的长期风险。**暂缓，已记录在案。**
