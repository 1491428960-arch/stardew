# Stardew AI NPC 双入口对话体验设计（历史草案）

> 本文档是 2026-08-23 的历史草案，曾包含 Smartphone 入口。当前方案已改为原生风格聊天界面，不接入 Smartphone；请以 [2026-08-24 原生风格 AI 聊天界面设计](superpowers/specs/2026-08-24-native-chat-ui-design.md) 为准。

## 1. 背景与结论

当前 `DialogueMenu` 是链路验证原型：固定尺寸、固定发送“你好”、直接绘制未换行文本。它证明了 SMAPI → Bridge → Provider 的调用链，但不具备可用的聊天体验。

本阶段不重新实现完整游戏 UI，也不全局替换 NPC 对话。最终采用以下组合：

- **面对面入口：** 复用 Stardew Valley 原生 `DialogueBox`。玩家按原交互键后，先完整显示原版寒暄，再自愿进入 AI 自由聊天。
- **手机入口：** 通过公开 API 接入外部 `Smartphone` Mod，复用手机外壳、快捷键、主题、缩放、拖动和导航。本项目只注册 AI 聊天应用。
- **统一对话层：** 两个入口共用现有 `BridgeClient`、NPC 上下文采集和按 NPC 隔离的短期历史。

该方案优先保证原版兼容性、低维护成本和 Bridge 故障时的安全退化。

## 2. 目标与非目标

### 2.1 目标

1. 玩家面对 NPC 按原交互键时，原版每日台词、剧情对话和既有 Mod 对话仍先执行。
2. 原版寒暄关闭后，提供「继续聊聊」和「先告辞」两个选择。
3. 进入 AI 环节后，玩家可以自由输入，NPC 回复使用原生头像对话框并自动换页。
4. 玩家可以通过 Smartphone 打开 AI 聊天应用，不必走到 NPC 身边。
5. 面对面和手机入口共享同一个 NPC 的当前运行期对话历史。
6. Bridge 离线、超时或返回异常时，不阻断游戏，也不破坏原版对话。

### 2.2 非目标

- 不拦截并替换所有原版 NPC 台词。
- 不复制 Smartphone 的完整源码、素材、社交、相机或照片功能。
- 不在本阶段让 AI 改写任务、好感度、NPC 日程或剧情状态。
- 不重做已经完成的 GMCM、F8 配置、NPC 双 ID 兼容、Bridge 回退链路和快速 profile。
- 不在第一版支持节日、过场事件和多人分屏中的面对面续聊；这些场景默认保持原版行为。

## 3. 复用边界

| 能力 | 来源 | 本项目职责 |
|------|------|------------|
| NPC 原版寒暄、头像框、文本分页 | Stardew Valley 原生 `DialogueBox` | 监听对话生命周期，不修改原版文本 |
| 玩家自由输入 | 本项目轻量输入菜单 | 输入、发送、取消、等待状态和错误提示 |
| AI 请求与短期历史 | 现有 `BridgeClient` | 两个入口调用同一实例 |
| NPC、地点、时间、关系上下文 | 现有 `GameStateCollector` | 发送每轮最新状态 |
| 手机外壳、快捷键、主题、缩放、拖动和导航 | 外部 `Smartphone` Mod | 通过 API 注册 AI Chat 应用 |
| 手机联系人和聊天内容 | 本项目 Smartphone 应用页 | 选择 NPC、显示消息、自由输入 |

Smartphone 以独立 Mod 形式安装。本项目不分发其 DLL 或素材，只保留最小 API 接口声明和运行时检测。

## 4. 面对面交互流程

### 4.1 正常流程

1. 玩家面向 NPC，按游戏原交互键。
2. Mod 只记录本次候选 NPC，不拦截按键，游戏照常打开原版 `DialogueBox`。
3. 玩家读完并关闭全部原版对话页。
4. Mod 确认该对话由刚才的 NPC 交互产生，并显示原生选择框：
   - 「继续聊聊」
   - 「先告辞」
5. 选择「继续聊聊」后打开轻量输入菜单。
6. 发送消息后，输入菜单进入不可重复提交的等待状态。
7. Bridge 返回后，使用 NPC 头像对应的原生 `DialogueBox` 展示回复；长回复由游戏原生分页能力处理。
8. NPC 回复关闭后重新打开输入菜单，直到玩家按 Esc、点击「结束聊天」或离开有效场景。

### 4.2 不触发续聊的场景

以下情况只保留原版行为：

- 正在播放事件或过场动画；
- 节日场景；
- 游戏暂停、存档切换或尚未进入世界；
- 玩家交互的不是 NPC；
- 对话不是由当前记录的 NPC 交互产生；
- 已有其他菜单接管流程；
- 配置中关闭 AI 对话。

### 4.3 生命周期状态

面对面协调器使用明确状态，避免一次原版对话重复弹出续聊选择：

```text
Idle
  → AwaitingVanillaDialogue
  → VanillaDialogueOpen
  → AwaitingContinuationChoice
  → Composing
  → WaitingForBridge
  → ShowingNpcReply
  → Composing
  → Idle
```

任意状态遇到存档退出、返回标题、NPC 失效或菜单被其他流程替换时，都回到 `Idle`。

## 5. AI 对话 UI

### 5.1 NPC 回复

- 继续使用游戏原生 `DialogueBox`，显示 NPC 名称、头像和逐字文本。
- 不在游戏画面上直接调用 `DrawString` 绘制长回复。
- 不自行维护回复区域的换行和分页。
- Provider、成功状态和技术错误不混入 NPC 台词。

### 5.2 玩家输入

轻量输入菜单只包含：

- 当前 NPC 名称；
- 单行或可滚动输入框；
- 「发送」和「结束聊天」按钮；
- 请求期间的「正在思考……」状态；
- 可恢复的简短错误提示。

输入菜单必须支持键盘输入、鼠标点击、Enter 发送和 Esc 退出。发送期间禁用重复提交，但允许取消当前会话。

### 5.3 错误呈现

- Bridge 离线或超时：输入菜单显示简短提示，并允许重试或退出。
- 无效响应：向 SMAPI 日志写详细信息，游戏内只显示可理解的短消息。
- Smartphone 缺失：不注册手机应用；面对面入口与原 F8 备用入口继续工作。

## 6. Smartphone 集成

### 6.1 依赖方式

`manifest.json` 将 `d5a1lamdtd.Smartphone` 声明为可选依赖：

- 已安装：在 `GameLaunched` 后获取 `ISmartPhoneApi`，注册 AI Chat 应用。
- 未安装：记录一次提示日志，不影响 Mod 加载和面对面聊天。

快速测试 profile 在手机阶段加入固定版本的 Smartphone，用于真实游戏冒烟测试。

### 6.2 应用范围

手机应用第一版只实现：

1. 已认识 NPC 联系人列表；
2. 当前 NPC 的运行期消息历史；
3. 文本输入、发送、等待和错误状态；
4. 返回 Smartphone 首页。

当天首次打开某个 NPC 的聊天时，可以把当日原版寒暄作为上下文提示展示，但不得重复发放原版每日交谈带来的好感收益。

### 6.3 许可证边界

Smartphone 仓库采用 GPL-3.0。本项目只通过公开 SMAPI API 与其交互，不复制其实现和素材。若以后决定 fork 或直接合并源码，必须先单独确定本项目许可证、署名和源代码发布方式；本阶段不做此扩展。

## 7. 代码结构

建议新增或替换以下职责：

```text
smapi/
  ConversationService.cs                 # 两个入口共用的发送、状态和历史访问
  FaceToFaceConversationCoordinator.cs   # 原版对话结束后的续聊状态机
  ChatInputMenu.cs                        # 面对面轻量输入菜单
  SmartphoneIntegration.cs               # API 检测与应用注册
  SmartphoneChatMenu.cs                  # 手机联系人和消息界面
  ISmartPhoneApi.cs                       # 最小公开 API 接口声明
```

现有 `DialogueMenu.cs` 在新流程通过测试后移除；`BridgeClient`、`GameStateCollector` 和 `NpcTargetResolver` 保留并复用。

`F8` 暂时保留为开发和故障排查入口，但改为直接打开同一个聊天服务，不再维护独立对话实现。

## 8. 测试策略

按照测试先于实现的规则，先增加以下自动化测试：

### 8.1 状态机测试

- 普通 NPC 原版对话关闭后只出现一次续聊选择；
- 选择「先告辞」立即回到 `Idle`；
- 选择「继续聊聊」进入输入状态；
- 事件、节日、非 NPC 交互不会进入 AI 流程；
- 存档退出和返回标题会清理待处理状态；
- Bridge 返回、超时和异常都能结束等待状态。

### 8.2 UI 与服务测试

- 空消息不能发送；
- 长消息沿用现有长度限制；
- 同一 NPC 的两个入口共享历史，不同 NPC 互相隔离；
- 请求期间不能重复发送；
- 退出菜单后异步回复不会覆盖其他游戏菜单。

### 8.3 Smartphone 集成测试

- API 存在时只注册一次应用；
- API 缺失或版本不兼容时安全跳过；
- 应用点击后打开正确菜单；
- 返回、缩放和拖动事件交给 Smartphone API；
- 未安装 Smartphone 时面对面测试仍全部通过。

### 8.4 验证顺序

1. 运行 SMAPI C# 单元测试；
2. 运行 Bridge 测试；
3. 运行快速 profile 脚本测试；
4. 在 Fake Provider 下进行面对面冒烟测试；
5. 加载 Smartphone 后进行手机入口冒烟测试；
6. 关闭 Bridge，确认两个入口均可安全退出且游戏继续运行。

## 9. 实施顺序

1. 提取统一 `ConversationService`，以现有 F8 入口做回归保护。
2. 实现面对面状态机和原版寒暄后的续聊选择。
3. 用 `ChatInputMenu` 和原生 `DialogueBox` 替换当前不可用的 `DialogueMenu`。
4. 接入 Smartphone API 并注册 AI Chat 应用。
5. 实现手机联系人和消息页。
6. 更新快速 profile、README、测试用例和交接文档。
7. 完成 Fake Provider 与真实游戏冒烟验证。

## 10. 验收标准

- 原版对话在未选择续聊时与未安装本 Mod 的表现一致。
- 面对面 AI 聊天不再出现文字越界、状态文字叠加或固定发送“你好”的问题。
- 手机框架的快捷键、外壳、缩放和导航由 Smartphone 提供。
- 面对面和手机可以与同一 NPC 连续聊天，并共享当前运行期上下文。
- Smartphone 或 Bridge 任一缺失时，游戏仍能正常游玩和退出。
- 自动化测试全部通过，快速 profile 中无新增 SMAPI 红色错误。
