# docs 目录说明

> 最后更新：2026-09-20。本文件只解释**目录结构**，不重复内容；具体状态请看 `active-work.md` 的**末尾**。

## 先看这几份

| 想看什么 | 打开 |
|---|---|
| 项目现在什么状态、这一夜做了什么、醒来该复核什么 | `overnight-report-2026-09-20.md` |
| 群聊这条线的现状与交接（含五个视觉场景、十条坑） | `handoff-group-dialogue-2026-09-20.md` |
| 还剩哪些事、哪些需要你拍板 | `next-steps-2026-09-20.md` |
| 完整工作日志（**最新条目在文件末尾**） | `active-work.md` |
| **当前值的唯一权威源**（测试数、覆盖率等只维护在这里） | `.dsh/memory/current-state.md` |

## 目录结构约定

| 前缀 | 含义 | 是否要维护 |
|---|---|---|
| `active-work.md` | 权威工作日志，逐项带测试证据 | **每次工作都要追加**（写在**文件末尾**） |
| `overnight-report-*.md` | 长时自主作业的总结与复核清单 | 当日产物，事后归档 |
| `handoff-*.md` | 交接文档（给下一个会话／另一个人） | 状态变化时更新，作废的在头部标注 |
| `next-steps-*.md` | 待办清单（A 需拍板／B 可直接做／C 已判定不做） | 状态变化时更新 |
| `diagnosis-*.md` | 问题诊断记录（例如另一条工作线的失败归因） | 一次性，留档 |
| `deploy-*.md` | 部署到正式环境的检查清单 | 部署流程变化时更新 |
| `design-*.md` | 交互与体验设计稿 | 历史记录，不再更新 |
| `report-*.md` | 研究报告（社区调研、方案对比、路线评估） | 历史记录，**不再更新**（要改就写新报告） |
| `npc-bubble-elements-*.md` / `.json` | 气泡元素规格（另一条工作线产出） | 由该线维护 |
| `superpowers/` | 计划与规格（`plans/`、`specs/`） | 历史记录 |
| `test-cases.md` | 人工回归清单（游戏内步骤） | 环境变化时在顶部补提示 |

## 写文档的两条约定

1. **时间敏感的事实要带日期**——例如写“当前测试基线 N passed（YYYY-MM-DD）”时**必须同时给出取数日期**，否则几个月后会变成误导；而**具体的当前值只维护在 `.dsh/memory/current-state.md` 一处**，其余文档引用它、不要各自复制一份。
2. **不要在多处复制同一份状态**：状态写在 `active-work.md`，其他文档用**指针**指向它——这也是 `.dsh/memory/` 被改写成指针的原因。
