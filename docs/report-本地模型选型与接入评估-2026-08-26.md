# 本地模型选型与接入评估

日期：2026-08-26
研究问题：本地模型选型与接入评估

## 结论

本机接入不应继续使用 Fake Provider；在当前硬件上，最值得优先验证的是 **Ollama + Qwen3.5 9B `Q4_K_M`**，同时保留 **Qwen3.5 4B `Q4_K_M`** 作为低延迟/低占用档。

推荐顺序：

1. **质量优先候选：Qwen3.5 9B Q4_K_M**，模型文件约 6.6 GB。官方同一张评测表中，它的 C-Eval、IFEval、MMLU-ProX、WMT24++ 分别为 88.2、91.5、76.3、72.6，高于 Qwen3.5 4B 的 85.1、89.8、71.5、66.6；这只能说明通用能力更强，不能直接等同于 Rasmodia 角色扮演质量。
2. **稳妥候选：Qwen3.5 4B Q4_K_M**，模型文件约 3.4 GB，预计更容易与游戏同时运行。它支持中文和多语言、文本/图像输入，官方提供 OpenAI-compatible 接入示例。
3. 不建议一开始下载 14B 以上模型：Qwen3 14B Q4 已约 9.3 GB，运行时还要占用 KV cache 和框架开销；在 16 GB 内存、游戏和 Bridge 同时运行时，延迟与稳定性风险明显增加。

本轮已完成真实 Ollama 链路的第一轮验证：`qwen3.5:4b` 在独立 Ollama 实例中完成 7 个 Rasmodia 场景，6/7 通过、0 errors，平均耗时约 2557.4 ms；`qwen3.5:9b` 完成同一套场景，7/7 通过、0 errors，平均耗时约 3723.6 ms。评测现在对声明的期望词至少要求命中 1 项，并对“未触发事件”增加场景级矛盾断言拦截。唯一未通过的 4B 场景是同日续聊：回复使用“它”承接，但没有足够的咖啡/饮品证据词；9B 明确复述了咖啡和后续状态。两份工件均按同一规则生成。若 9B 延迟影响游戏，再切换 4B，而不是同时长期驻留两个模型。

流式性能也已完成第一轮实测：热模型（排除首个冷启动请求）4B 首段内容延迟约 320.8 ms、生成速度约 96.68 tok/s；9B 约 420.3 ms、64.22 tok/s。首次加载请求额外耗时约 4.38 s（4B）和 7.11 s（9B），因此游戏内应保持单模型常驻，不能用冷启动延迟代表普通聊天体验。

## 判断依据

### 本机资源事实

- 当前 `nvidia-smi` 实测为 **NVIDIA GeForce RTX 3070 Laptop GPU，8 GB 显存，驱动 572.60，Compute Capability 8.6**；系统可用内存约 16 GB。此前记录的 GTX 750 Ti 与当前实测不一致，本报告以当前实测为准。
- 本轮复核的磁盘可用空间约为：C 盘 5.9 GiB、D 盘 105.6 GiB、E 盘 212.0 GiB。C 盘不适合放模型或 Ollama 模型缓存。
- Ollama 官方 Windows 文档称安装程序本身至少需要约 4 GB，模型另占空间，并支持通过 `OLLAMA_MODELS` 改变模型目录。因此应把安装目录和模型目录放在 D/E 盘；不能把默认 `%HOMEPATH%\\.ollama\\models` 当作长期方案。

### 候选模型与空间

| 候选 | 官方 Ollama Q4_K_M 文件大小 | 上下文标称值 | 对本项目的判断 |
|---|---:|---:|---|
| Qwen3.5 4B | 3.4 GB | 256K | 最稳妥的游戏内实时聊天档；角色细节和长对话一致性低于 9B 的可能性较大（推断）。 |
| Qwen3.5 9B | 6.6 GB | 256K | 质量优先档；8 GB 显存可以尝试，但要限制上下文并观察与游戏并行时的显存占用（推断）。 |
| Qwen3 4B | 2.6 GB | 40K | 体积最小，并且官方明确强调 creative writing、role-playing、multi-turn；作为兼容性备选。 |
| Qwen3 8B | 5.2 GB | 40K | 旧一代质量/占用折中；没有足够理由优先于更新的 Qwen3.5 9B。 |

模型文件大小不是运行时总内存。上下文越长，KV cache 越大；Qwen3.5 官方也提示遇到 OOM 时应降低 context length。对游戏聊天，首轮应把上下文限制在 8K～16K，依靠已有 profile index/RAG 注入相关资料，而不是盲目开启 256K。

### 效果与接入可行性

- Qwen3.5-4B 官方卡标注支持 201 种语言/方言，并报告了 C-Eval 85.1、MMLU-ProX 71.5、IFEval 89.8 等结果；9B 对应为 88.2、76.3、91.5。评测来自模型作者，适合做候选排序，不代表真实游戏对话的主观体验。
- Qwen3 系列官方明确把非思考模式定位为高效通用对话，并强调角色扮演和多轮对话；这与 Rasmodia 的短回合聊天更匹配。Qwen3.5 默认会生成 `<think>` 内容，官方建议通过 API 参数关闭思考；接入时必须显式关闭，否则会增加延迟并可能把思考标记带到游戏文本。
- 当前 Bridge 同时提供 `OpenAICompatibleProvider` 和 `OllamaNativeProvider`（由 `BRIDGE_LOCAL_API_MODE=ollama` 选择）；原生模式调用 `/api/chat`，固定发送 `stream:false`、`think:false`，保留 `/v1/chat/completions` 兼容模式给 Ollama/LM Studio 等其他后端。Ollama 官方文档给出了两种接口示例；LM Studio 也提供本地 OpenAI-compatible server。
- Ollama 官方硬件文档列出 RTX 3070（Compute Capability 8.6）为支持卡；本机驱动 572.60 满足其文档中的驱动门槛。实际能否把 9B 完整驻留显存仍需启动后测量，不能只凭型号推断。

### 运行时选择

- **Ollama（推荐）**：服务常驻、命令行可复现、原生提供 OpenAI-compatible API，且模型目录可用 `OLLAMA_MODELS` 放到 D/E 盘，适合 Bridge 和一键启动脚本。
- **LM Studio（备用）**：GUI 更适合手动比较模型和显存分配；官方建议 Windows 至少 16 GB 内存、4 GB 专用显存，并提供 OpenAI-compatible API。但它的 GUI/模型加载状态会让自动化测试更依赖桌面状态。

## 建议

1. **首选验证**：Ollama + `qwen3.5:9b-q4_K_M`，模型和 Ollama 安装放 D 盘或 E 盘，预留至少 12 GB 空间；当前 4B 与 9B 均已下载并完成离线验证，下一步只需比较游戏并行帧率影响。
2. **服务参数**：为游戏创建单独的 Ollama Modelfile，把 `num_ctx` 设为 8192 或 16384；Bridge 原生模式已经显式走非思考模式，并将输出上限控制在适合游戏对话的范围。仍需用真实 Ollama 版本做小测试。
3. **TDD 接入**：已补测试，验证原生 Ollama payload 的非思考控制、响应解析和路由选择；Fake Provider 只保留为离线演示，不再冒充真实 AI。
4. **离线基准**：固定同一套 Rasmodia 题目（身份、魔法师背景、SVE/RomRas 来源区分、同日多轮记忆、中文自然度、拒答/越界），分别测 9B 和 4B 的请求总耗时、输出长度、轻量证据词命中和场景级矛盾断言。当前实测：4B 为 6/7、0 errors、平均约 2557.4 ms；9B 为 7/7、0 errors、平均约 3723.6 ms。流式实测的热请求首段延迟/生成速度约为 4B 321 ms / 96.68 tok/s、9B 420 ms / 64.22 tok/s；差异主要落在同日多轮记忆的明确复述和 9B 更高的上下文质量。
5. **接入验证**：安装并启动 Ollama → `GET /api/tags` 确认模型名 → 用 `scripts/benchmark_local_models.py` 走真实 `/api/chat` → 记录原文、provider、latency、fallback 和轻量评分 → 再部署 SMAPI DLL。4B 与 9B 的链路均已完成；游戏默认模型仍以并行帧率和实际对话体验共同决定。
6. **游戏并行测量**：在隔离 profile 的 `config.json` 临时开启 `EnablePerformanceDiagnostics`，Mod 每 5 秒输出一条 `[StardewAI.Perf]` 帧率窗口；分别在 4B/9B 常驻、未聊天与正在生成回复时采样，比较同一存档和场景的 FPS，测完恢复默认关闭。

## 限制

- 4B/9B 各完成一轮非流式和一轮流式离线基准；游戏内并行帧率仍待实际会话采集。模型输出具有随机性，最终质量取舍仍应结合多轮重复和游戏内体验。首段内容延迟是“收到首个非空内容块”的工程指标，不等同于模型内部严格的首 token 时间。
- 官方 benchmark 是模型作者提供的通用评测，不包含 Rasmodia、Stardew Valley 或中文角色扮演专门评分；最终选择仍以项目固定题集的人工/规则评分为准。
- Qwen3.5 默认上下文标称 256K，但本机内存和游戏并行不适合直接使用该上限；报告建议的 8K～16K 是工程取舍，不是模型能力上限。
- Ollama/LM Studio 版本、驱动和量化文件会更新，下载时应重新核对 tag 大小和 API 行为；模型文件大小也不等于运行时内存。
